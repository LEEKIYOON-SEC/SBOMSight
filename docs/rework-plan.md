# SBOMSight 개편 계획 (N 시리즈)

지금 상태의 문제는 색·글꼴이 아니다. **무엇이 어디에 있어야 하는가를 잘못 정해 놓고,
그 위에 화면을 그렸다.** 이 문서는 그것을 다시 정한다.

기능은 거의 다 있다. 지우는 것과 옮기는 것이 대부분이고, 새로 만드는 것은 적다.
**DB 스키마 변경은 없다** — 마이그레이션 V11 은 필요하지 않다.

## 1. 정보 구조

### 지금 (기둥 7 + 구역 n)

```
자산 / 전사 조회 / 구역 보고서 / 조치 / 위험 수용 / 감사 로그 / 설정
─────────────────────────────
ZONE  DMZ · 내부업무 · 미분류 …
```

문제: 같은 것이 두 군데(구역·구역 보고서), 목록만 있고 입구가 없는 것(위험 수용),
자산의 거르개가 기둥에 올라온 것(ZONE), 관리자만 쓰는 것이 상시 노출(감사 로그).

### 바꿀 것 (기둥 5)

| 기둥 | 주소 | 무엇 | 흡수하는 것 |
|---|---|---|---|
| **자산** | `/` | 서버 목록·구역 묶음·구역 관리·등록 | 구역 목록, 설정의 구역 표, 구역 현황 시안 |
| **취약점** | `/vulns` | 범위를 골라 보는 탐지 목록 | 전사 조회, `/scans/{id}` |
| **대응** | `/actions` | ① 조치 ② 위험 수용 | 조치, 위험 수용 |
| **보고서** | `/reports` | 범위·기간을 골라 뽑는다 | 구역 보고서, `/report/{scanId}` |
| **설정** | `/settings` | 계정 · 접근 IP · 도구 · **감사 로그** | 감사 로그 |

기둥 아래: 계정 블록 → **`/me`**.

원칙 — **기둥에 올릴 자격은 "자산을 거치지 않고 물을 수 있는 질문"이다.**
"이 CVE 가 어디에 있나"(취약점), "기한 지난 게 있나"(대응), "보고서 뽑자"(보고서)는 자격이 있다.
"DMZ 서버 보여 줘"는 자산의 거르개다. 기둥이 아니다.

## 2. 화면 명세

### 2.1 자산 `/`

```
자산                                    [구역 관리] [일괄 등록] [자산 등록]
검사 안 한 서버 3 · 30일 넘은 서버 2 · 기한 지난 조치 4 · 심각 21 · 수정본 없음 44
   ↑ 각 숫자가 링크다. 누르면 그 조건이 걸린 화면으로 간다.

[전체 24] [■DMZ 8] [■내부업무 12] [미분류 4]        보기: [표] [구역]
```

- **요약 줄**: 한 줄. 카드 벽을 만들지 않는다. 0 인 항목은 안 그린다.
  - `검사 안 한 서버` → `/?filter=noscan`
  - `30일 넘은 서버` → `/?filter=stale`
  - `기한 지난 조치` → `/actions?overdue=true`
  - `심각` → `/vulns?severity=Critical`
  - `수정본 없음` → `/vulns?fix=none`
- **구역 칩**: 거르개. 선택은 URL(`?zone=3`)에 남는다.
- **보기 전환**
  - `표` — 지금 구조 유지(구역 머리줄 + 서버 행). 헤더 클릭 정렬 추가.
  - `구역` — 시안의 카드 격자. 카드 = 구역 이름 · 서버 수 · 기한 경과 배지 ·
    큰 수치(심각+높음) · 심각도 막대 · 심각도 건수 · **그 구역 서버 목록(이름+탐지 수)** ·
    바닥에 `가장 오래된 검사 2026-08-01` · `⋮`(이름 바꾸기·색·삭제·보고서).
    서버가 카드 안에 있으므로 카드를 눌러 다른 화면으로 튕기지 않는다.
- **구역 관리**: 머리의 `구역 관리` → 팝업. 추가 · 이름 · 색 · 삭제(자산 있으면 불가).
  `설정 → 구역` 은 삭제한다.
- 정렬: 서버 이름 / 마지막 검사 / 탐지 / 심각. `?sort=&dir=`.

### 2.2 취약점 `/vulns`

```
취약점                                                   [CSV 내려받기]
범위 [전체 ▾]  묶기 [항목별|CVE별|패키지별]
검색[            ] 심각도[▾] 수정본[▾] 실제악용[▾] 수용된것[감추기▾]   [찾기]
```

- **범위** — `?asset=` · `?zone=` · `?scan=` · 없으면 전체.
  - `asset`/`zone` 은 **각 자산의 가장 최근 완료 검사**를 본다.
  - `scan` 은 그 검사 하나. 검사 이력의 `열기` 가 여기로 온다.
  - 머리줄에 범위를 글자로 못 박는다: `web-01 · 2026-09-10 14:22 검사 · 98건`.
- **묶기**
  | 모드 | 한 줄 | 열 |
  |---|---|---|
  | 항목별 | 탐지 1건 | 자산·취약점·심각도·CVSS·악용확률·패키지·설치→수정·상태 |
  | CVE별 | CVE 1건 | CVE·심각도·CVSS·**영향 서버 수**·**구역 분포**·패키지·수정본 유무 |
  | 패키지별 | 패키지 1건 | 패키지·현재→목표·탐지 수·최고 심각도·영향 서버 수 |
  - CVE별·패키지별은 펼치면 어느 서버인지 나온다.
- **행 액션**(관리자): `[조치]` `[수용]` — 그 자리에서 팝업. 이것이 6번 지적의 답이다.
- 정렬: 심각도 / CVSS / 악용확률 / 패키지 / 영향 서버 수. 값이 없는 것은 **방향과 무관하게 항상 뒤로**.
- 거르개·정렬·쪽은 전부 URL 에 남는다.
- `/lookup`, `/scans/{id}` 는 여기로 넘긴다(302).

### 2.3 대응 `/actions`

```
대응                                                     [CSV 내려받기]
[조치 12]  [위험 수용 5]                     구역[▾] 서버[▾] 상태[▾]
```

- **조치 탭** — 지금 `/remediations`. 기한 지난 것은 위로.
- **위험 수용 탭** — 지금 `/acceptances`. 다시 볼 날 지난 것 위로.
- 등록은 여기서 하지 않는다. **취약점 화면에서 한다** — 수용은 "이 취약점을 안 고친다"는
  결정이므로 취약점 옆에 있어야 한다. 이 화면은 결정들을 모아 보는 자리다.
- 배지: 기한 경과 수(붉게).

### 2.4 보고서 `/reports`

```
보고서
범위 [서버 ▾][web-01 ▾]   또는 [구역 ▾][DMZ ▾]   또는 [전체]
기간 [2026-08-01] ~ [2026-09-12]                        [보고서 만들기]

최근에 만든 것
  web-01 · 2026-09-10 검사 기준            [열기] [인쇄]
```

문서 형식 (**기승전결 폐기**, §11):

```
             web-01 취약점 점검 결과 보고

문서 정보    작성일 2026-09-12 │ 작성자 홍길동 │ 점검 대상 web-01 (DMZ)
             점검 일시 2026-09-10 14:22 │ 점검 도구 grype 0.87.0 (DB 2026-09-09)

1. 점검 개요            표 — 대상·운영체제·SBOM 파일·컴포넌트 수·탐지 건수
2. 점검 결과 요약       표 — 심각도별 건수/비중 · 수정 가능/불가 · 실제 악용
                        표 — 접근 경로별(원격·인증불필요·권한경계) *
3. 조치 대상            표 — 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 영향
4. 수정본 없는 항목     표 — 패키지 · 건수 · 최고 심각도 · 수용 여부 · 사유
5. 조치 진행 현황       표 — 패키지 · 상태 · 담당 · 기한
6. 이전 검사 대비       표 — 신규 / 해소 / 유지
[붙임] 전체 탐지 목록   표 (선택)

* 각주: AV:N 원격, PR:N 인증 불필요, UI:N 사용자 개입 불필요. 판단 불가 n건.
```

- **서술형 문단 0개.** 지금의 `class="lead"` 문단, `기/승/전/결` 표시, 표 안의 "뜻" 칸을
  전부 없앤다. 설명이 필요한 약어는 **표 아래 각주 한 줄**로.
- 인쇄: A4 세로, 표 머리 반복(`thead { display: table-header-group }`),
  장 사이 `page-break-before`, 쪽 번호.
- 구역·기간 보고서(`ZoneReportService`)도 같은 형식으로 맞춘다.

### 2.5 설정 `/settings` (관리자)

```
설정   [계정] [접근 IP] [도구] [감사 로그]
```

- **계정** — 행마다 `[수정] [비밀번호 초기화] [삭제]`. 권한 드롭다운 즉시 저장 제거.
  `수정` 팝업: 이름 · 권한 · 사용 여부 · **새 비밀번호(비우면 안 바꿈)** · 잠금 해제.
- **구역 표는 여기서 삭제** (자산 화면으로).
- **감사 로그** 탭으로 들어온다. 기둥에서 뺀다.

| | |
|---|---|
| 계정 | `admin` |
| 이름 | 홍길동 · 인프라운영팀 &nbsp; `[바꾸기]` |

| 비밀번호 변경 | 2026-06-01 (103일 전) &nbsp; `[비밀번호 변경]` |

기둥 아래 계정 블록 전체가 이 화면으로 간다. `/password` 는 남기되 여기서만 들어간다.

### 2.7 자산 상세 `/assets/{id}`

- 머리: 이름 · 구역 · OS · 비고 + `[취약점 98건] [보고서] [SBOM 올리기]`
- 검사 진행 카드 — 그대로 (L1 에서 만든 것).
- 검사 이력 — **액션 열을 `[열기] [다시 검사] [삭제]` 같은 버튼으로** (8번 지적).
- 그 서버의 조치 / 위험 수용 (7번 지적).
- 자산 삭제 — 맨 아래 유지.

## 4. 공통 규칙 (앱 전체)

1. **행 액션은 전부 `btn small`.** 맨 링크와 버튼을 한 칸에 섞지 않는다.
   목록의 이름(자산명·패키지명)만 링크다.
2. **파괴적 동작은 `btn small danger` + 확인.** 지금 규칙 유지.
3. **거르개·정렬·쪽은 URL 에.** 새로고침·공유·뒤로가기가 살아 있어야 한다.
4. **없는 값은 `—`.** 0 이나 `false` 로 채우지 않는다 (CLAUDE.md 6).
5. **빈 화면에는 다음 버튼 하나.** 설명 두 줄 이상 쓰지 않는다.
6. **표 머리 클릭 정렬**, 값 없는 행은 방향과 무관하게 뒤로.
7. **문장을 화면에 쓰지 않는다.** 필요하면 `<details class="help">` 안으로.
8. **한 화면에 `<h2>` 넷을 넘기면 탭으로 가른다.**
9. 숫자는 `num` 클래스(탭 정렬), 세 자리 쉼표.
10. 모든 팝업은 `<dialog>` + `showModal()`, 취소는 왼쪽, 실행은 오른쪽 `primary`.
