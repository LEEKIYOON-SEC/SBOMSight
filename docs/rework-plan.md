# SBOMSight 개편 계획 (N 시리즈) · rev.2

지금 문제는 색·글꼴이 아니다. **무엇이 어디에 있어야 하는가를 잘못 정해 놓고,
그 위에 화면을 그렸다.** 이 문서는 그것을 다시 정한다.

**rev.2 에서 더한 것** — 같은 일을 하는 공개 도구
[OWASP Dependency-Track](https://dependencytrack.org/) 의 화면 구성을 확인하고,
가져올 것과 가져오지 않을 것을 §8 에 못 박았다. 그 결과 rev.1 에 없던 것 세 가지가
들어왔다: **심각도 막대**, **판정(VEX) 어휘**, **패키지 인벤토리**.
이 때문에 rev.1 의 "DB 스키마 변경 없음" 은 **틀렸다** — V11 · V12 가 필요하다.

## 1. 정보 구조

### 지금 (기둥 7 + 구역 n)

```
자산 / 전사 조회 / 구역 보고서 / 조치 / 위험 수용 / 감사 로그 / 설정
─────────────────────────────
ZONE  DMZ · 내부업무 · 미분류 …
```

같은 것이 두 군데(구역·구역 보고서), 목록만 있고 입구가 없는 것(위험 수용),
자산의 거르개가 기둥에 올라온 것(ZONE), 관리자만 쓰는 것이 상시 노출(감사 로그).

### 바꿀 것 (기둥 5 + 1)

| 기둥 | 주소 | 무엇 | 흡수하는 것 |
|---|---|---|---|
| **자산** | `/` | 서버 목록 · 구역 묶음 · 구역 관리 · 등록 | 구역 목록, 설정의 구역 표, 구역 현황 시안 |
| **취약점** | `/vulns` | 범위를 골라 보는 탐지 목록 · 판정 | 전사 조회, `/scans/{id}` |
| **패키지** | `/packages` | 어느 서버에 무엇이 몇 버전으로 깔려 있나 | **새로 생김** (§8-C) |
| **대응** | `/actions` | ① 조치 ② 판정·수용 | 조치, 위험 수용 |
| **보고서** | `/reports` | 범위·기간을 골라 뽑는다 | 구역 보고서, `/report/{scanId}` |
| **설정** | `/settings` | 계정 · 접근 IP · 도구 · **감사 로그** | 감사 로그 |

기둥 아래: 계정 블록 → **`/me`**.

> **기둥에 올릴 자격은 "자산을 거치지 않고 물을 수 있는 질문"이다.**
> "이 CVE 가 어디에 있나"(취약점), "openssl 이 어디에 깔려 있나"(패키지),
> "기한 지난 게 있나"(대응), "보고서 뽑자"(보고서)는 자격이 있다.
> "DMZ 서버 보여 줘"는 자산의 거르개다. 기둥이 아니다.

## 2. 화면 명세

### 2.1 자산 `/`

```
자산                                    [구역 관리] [일괄 등록] [자산 등록]
검사 안 한 서버 3 · 30일 넘은 서버 2 · 기한 지난 조치 4 · 심각 21 · 수정본 없음 44
   ↑ 각 숫자가 링크다. 누르면 그 조건이 걸린 화면으로 간다.

[전체 24] [■DMZ 8] [■내부업무 12] [미분류 4]    보기:[표][구역]  □ 보관된 자산도
```

- **요약 줄** 한 줄. 카드 벽을 만들지 않는다. 0 인 항목은 안 그린다.
  `검사 안 한 서버`→`/?filter=noscan` · `30일 넘은 서버`→`/?filter=stale` ·
  `기한 지난 조치`→`/actions?overdue=true` · `심각`→`/vulns?severity=Critical` ·
  `수정본 없음`→`/vulns?fix=none`
- **구역 칩** 거르개. 선택은 URL(`?zone=3`)에 남는다.
- **보기 전환**
  - `표` — 구역 머리줄 + 서버 행. 헤더 클릭 정렬.
  - `구역` — 시안 카드 격자. 카드 = 구역명 · 서버 수 · 기한 경과 배지 · 큰 수치(심각+높음) ·
    **심각도 막대**(§8-A) · 심각도 건수 · **그 구역 서버 목록(이름+탐지 수)** ·
    바닥 `가장 오래된 검사 2026-08-01` · `⋮`(이름·색·삭제·보고서).
    서버가 카드 안에 있으므로 눌러서 다른 화면으로 튕기지 않는다.
- **심각도 열은 막대 하나로.** 지금의 `심각 3 높음 12 보통 61 낮음 111` 네 덩이를
  `▮▮▮▯▯▯▯…` 한 줄 + 숫자로 바꾼다.
- **구역 관리** 머리의 버튼 → 팝업(추가·이름·색·삭제). `설정 → 구역` 은 삭제.
- **보관된 자산** — `Asset.archivedAt` 은 있는데 화면이 없다. 체크 하나로 보이고/숨고,
  자산 상세에 `보관` 버튼. (삭제 말고 치우는 길)
- 정렬: 이름 / 마지막 검사 / 탐지 / 심각. `?sort=&dir=`

### 2.2 취약점 `/vulns`

```
취약점                                                   [CSV 내려받기]
범위 [전체 ▾]  묶기 [항목별|CVE별|패키지별]
검색[          ] 심각도[▾] 수정본[▾] 실제악용[▾] 판정[▾] □ 감춘 것도 보기   [찾기]
```

- **범위** `?asset=` · `?zone=` · `?scan=` · 없으면 전체.
  `asset`/`zone` 은 각 자산의 **가장 최근 완료 검사**. `scan` 은 그 검사 하나
  (검사 이력의 `열기` 가 여기로 온다). 머리줄에 범위를 못 박는다:
  `web-01 · 2026-09-10 14:22 검사 · 98건`
- **묶기**

  | 모드 | 한 줄 | 열 |
  |---|---|---|
  | 항목별 | 탐지 1건 | 자산 · 취약점 · 심각도 · CVSS · 악용확률 · 패키지 · 설치→수정 · **판정** |
  | CVE별 | CVE 1건 | CVE · 심각도 · CVSS · **영향 서버 수** · **구역 분포** · 패키지 · 수정본 |
  | 패키지별 | 패키지 1건 | 패키지 · 현재→목표 · 탐지 수 · 최고 심각도 · 영향 서버 수 |

  CVE별·패키지별은 펼치면 어느 서버인지 나온다.
- **행을 펼치면 판정 칸**(§8-B). 팝업이 아니라 제자리에서 펼친다 — 목록을 잃지 않는다.
- **CVE 상세** `/vulns/{cve}` — 설명 · CVSS 벡터 풀이 · 별칭(GHSA↔CVE) ·
  **이 CVE 가 있는 서버 전부** · 판정 이력. 지금은 CVE 를 눌러도 갈 곳이 없다.
- 정렬: 심각도 / CVSS / 악용확률 / 패키지 / 영향 서버 수.
  **값 없는 것은 방향과 무관하게 항상 뒤로.**
- 거르개·정렬·쪽 전부 URL 에. `/lookup`·`/scans/{id}` 는 302.

### 2.3 패키지 `/packages` — **새로 생김**

```
패키지                                                   [CSV 내려받기]
검색[openssl        ] 구역[▾] 유형[rpm ▾] □ 취약점 있는 것만        [찾기]

패키지        유형   설치된 서버   버전            취약점
openssl       rpm    12대          3.0.7(8) 3.0.9(4)   ■ 21
```

- 펼치면 서버별 설치 버전 목록.
- 없으면 **"이 패키지가 어디에 깔려 있나"에 취약점이 있을 때만 답할 수 있다.**
  지금이 그렇다 — `Scan` 에 `componentCount`(숫자 하나)만 있고 컴포넌트 행이 없다.
  SBOM 관리의 절반이 비어 있는 자리다. (§8-C)
- 자산 상세에도 `설치된 패키지` 구역.

### 2.4 대응 `/actions`

```
대응                                                     [CSV 내려받기]
[조치 12]  [판정·수용 5]                     구역[▾] 서버[▾] 상태[▾]
```

- **조치 탭** — 지금 `/remediations`. 기한 지난 것 위로.
- **판정·수용 탭** — 지금 `/acceptances`. 다시 볼 날 지난 것 위로.
  상태(§8-B)별 거르개.
- **등록은 여기서 하지 않는다. 취약점 화면에서 한다** — 판정은 "이 취약점을
  어떻게 할 것인가"의 답이므로 취약점 옆에 있어야 한다. 이 화면은 결정을 모아 보는 자리.
- 배지: 기한 경과 수(붉게).

### 2.5 보고서 `/reports`

```
보고서
범위 [서버▾][web-01▾]  /  [구역▾][DMZ▾]  /  [전체]
기간 [2026-08-01] ~ [2026-09-12]                        [보고서 만들기]

최근에 만든 것    web-01 · 2026-09-10 검사 기준        [열기] [인쇄]
```

**문서 형식 (기승전결 폐기)**

```
             web-01 취약점 점검 결과 보고

문서 정보    작성일 2026-09-12 │ 작성자 홍길동 │ 점검 대상 web-01 (DMZ)
             점검 일시 2026-09-10 14:22 │ 점검 도구 grype 0.87.0 (DB 2026-09-09)

1. 점검 개요            표 — 대상·운영체제·SBOM 파일·컴포넌트 수·탐지 건수
2. 점검 결과 요약       표 — 심각도별 건수/비중 · 수정 가능/불가 · 실제 악용
                        표 — 접근 경로별(원격·인증불필요·권한경계) *
3. 조치 대상            표 — 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 영향
4. 수정본 없는 항목     표 — 패키지 · 건수 · 최고 심각도 · 판정 · 근거
5. 조치 진행 현황       표 — 패키지 · 상태 · 담당 · 기한
6. 이전 검사 대비       표 — 신규 / 해소 / 유지   (기간 보고서는 월별 추이 표)
[붙임] 전체 탐지 목록   표 (선택)

* 각주: AV:N 원격, PR:N 인증 불필요, UI:N 사용자 개입 불필요. 판단 불가 n건.
```

- **서술형 문단 0개.** 지금의 `class="lead"` 문단, `기/승/전/결` 표시, 표 안의 "뜻" 칸
  전부 제거. 설명이 필요한 약어는 **표 아래 각주 한 줄**.
- **감춘 판정도 건수는 남긴다** — 보고서는 "탐지 187건 중 12건은 판정으로 감춤"을
  밝힌다. 감춰서 숫자가 줄어든 보고서는 점검에서 문제가 된다.
- 인쇄: A4 세로, `thead { display: table-header-group }`, 장 사이 `page-break-before`, 쪽 번호.
- `ZoneReportService` 도 같은 형식으로.

### 2.6 설정 `/settings` (관리자)

```
설정   [계정] [접근 IP] [도구] [감사 로그]
```

- **계정** 행마다 `[수정] [비밀번호 초기화] [삭제]`. **권한 드롭다운 즉시 저장 제거.**
  `수정` 팝업: 이름 · 권한 · 사용 여부 · **새 비밀번호(비우면 안 바꿈)** · 잠금 해제.
- **구역 표 삭제** (자산 화면으로).
- **감사 로그** 탭으로. 기둥에서 뺀다.

### 2.8 자산 상세 `/assets/{id}`

- 머리: 이름 · 구역 · OS · 비고 + `[취약점 98건] [보고서] [SBOM 올리기]` + **심각도 막대**
- 검사 진행 카드 — 그대로 (L1).
- 검사 이력 — 액션을 `[열기] [다시 검사] [SBOM 내려받기] [삭제]` **같은 버튼으로**.
  (보관해 둔 원본 SBOM 을 못 받는 것도 지금 빠진 것)
- 설치된 패키지 (N8 이후)
- 그 서버의 조치 / 판정·수용
- 보관 / 삭제

## 4. 공통 규칙

1. **행 액션은 전부 `btn small`.** 맨 링크와 버튼을 한 칸에 섞지 않는다.
   목록의 이름(자산명·패키지명)만 링크다.
2. 파괴적 동작은 `btn small danger` + 확인.
3. **거르개·정렬·쪽은 URL 에.** 새로고침·공유·뒤로가기가 살아야 한다.
4. **없는 값은 `—`.** 0 이나 `false` 로 채우지 않는다 (CLAUDE.md 6).
5. 빈 화면에는 다음 버튼 하나. 설명 두 줄 넘기지 않는다.
6. 표 머리 클릭 정렬. 값 없는 행은 방향과 무관하게 뒤로.
7. **문장을 화면에 쓰지 않는다.** 필요하면 `<details class="help">` 안으로.
8. 한 화면에 `<h2>` 넷을 넘기면 탭으로 가른다.
9. 숫자는 `num` 클래스(탭 정렬), 세 자리 쉼표.
10. 팝업은 `<dialog>` + `showModal()`. 취소 왼쪽, 실행 오른쪽 `primary`.
11. **목록 행의 심각도는 막대 하나로** (§8-A).

## 7. 손대지 않는 것

- **grype 판정** — 심각도·수정 버전·탐지 집합을 다시 계산하지 않는다.
  §8-B 의 판정은 **grype 의 결과를 바꾸는 것이 아니라 그 결과에 대한 우리의 결정**을
  따로 기록하는 것이다. 원본 건수는 어디서도 줄지 않는다.
- 검사 파이프라인(`ScanService`·`GrypeRunner`)과 진행 표시.
- 로그인·세션·IP 제한·잠금·비밀번호 주기.
- 기존 감사 로그 기록 지점.

## 8. 참고 — OWASP Dependency-Track

같은 일(SBOM 업로드 → 취약점 관리)을 하는 공개 도구. 화면 구성만 참고하고
판정 엔진은 참고하지 않는다 — **우리는 grype 하나를 믿기로 했고, 그쪽은 여러 분석기의
판정을 합친다.**

### 대응표

| Dependency-Track | 우리 | 상태 |
|---|---|---|
| Projects (목록) | 자산 | 있음 |
| Project Details → Overview | 자산 상세 | 있음 |
| Project Details → **Audit Vulnerabilities** | 취약점 + 판정 | **A·B 로 보강** |
| **Components** (전역 부품 목록) | 패키지 | **C — 없음** |
| Vulnerabilities (전역) | 취약점 CVE별 | 있음 (CVE 상세만 추가) |
| Administration | 설정 | 있음 |
| Dashboard (첫 화면) | — | **안 가져옴** (아래) |
| Policy Management | 조치 기한 규칙 | N9 [선택] |
| Dependency Graph · Teams · 분석기 관리 | — | 안 가져옴 |

### A. 심각도 막대 — **가져온다**

목록 한 줄에 `심각 3 · 높음 12 · 보통 61 · 낮음 111` 네 덩이를 쓰면 서버 20대를
세로로 훑을 수 없다. Dependency-Track 은 한 줄에 **누적 막대 하나**를 둔다.
같은 정보인데 눈이 한 번에 읽는다.

```
web-01   ▮▮▮▮▮▮▯▯▯▯▯▯▯▯▯▯▯▯▯▯   187
db-02    ▮▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯    23
```

구현 주의 — **0 이 아닌 구간은 최소 2px.** 안 그러면 심각 1건이 폭 0 으로 사라진다.

### B. 판정 어휘 (VEX) — **가져온다**

지금 위험 수용은 **빈 칸(`사유` textarea)** 이다. 그래서 "어떻게 쓰는지 모르겠다" 가 된다.
Dependency-Track 은 [CycloneDX VEX](https://cyclonedx.org/capabilities/vex/) 어휘로
**고르게** 한다. 고르는 항목은 스스로 사용법을 설명하고, 나중에 기계로 셀 수 있다.

**상태** (5 — Dependency-Track 과 같음)

| 값 | 뜻 |
|---|---|
| 미판정 | 아직 안 봤다 (기본) |
| 검토 중 | 우리에게 해당되는지 확인하고 있다 |
| 조치 대상 | 해당된다. 고쳐야 한다 |
| 해당 없음 | 맞는 탐지지만 우리 환경에는 영향이 없다 → **근거 필수** |
| 오탐 | 잘못된 탐지다 (패키지 오인 등) |

**근거** (`해당 없음` 일 때만, 9 — CycloneDX 표준)

코드 없음 · 실행 경로 아님 · 특정 설정 필요 · 특정 의존성 필요 · 특정 환경 필요 ·
컴파일러가 막음 · 런타임이 막음 · 경계에서 차단 · 대체 통제 있음

**대응** (5 — CycloneDX 표준)

고칠 수 없음 · 고치지 않음 · 업데이트 · 되돌리기 · 우회책 있음

**우리가 더하는 것** (규정상 필요, Dependency-Track 에 없음)
승인한 사람 · **다시 볼 날** · 대체 통제 설명

**감추기** — 판정한 건을 기본 목록에서 뺀다. 이력은 남는다.
**보고서에는 "탐지 187건 중 12건 감춤" 이 반드시 찍힌다** — 감춰서 숫자가 줄어든
보고서는 점검에서 문제가 된다.

**이력** — 누가 언제 무엇을 어떻게 바꿨는지 한 줄씩 쌓인다.
`RemediationEvent` 가 이미 같은 모양이라 그대로 따른다.

> 이것은 grype 의 판정을 바꾸는 것이 아니다. grype 은 "이 패키지에 이 CVE 가 있다"
> 고 말했고 그 말은 그대로 남는다. 우리가 기록하는 것은 **그 말에 대한 우리의 결정**이다.

### C. 패키지 인벤토리 — **가져온다**

Dependency-Track 의 Components 는 취약점과 **무관하게** "이 부품이 어느 프로젝트에
몇 버전으로 들어 있나" 에 답한다. 우리는 못 한다 — `Scan.componentCount` 숫자 하나만
있고 컴포넌트 행이 없다. **취약점이 있는 패키지만 알 수 있다.**

그래서 이런 질문에 답할 수 없다:
- "log4j 가 우리 서버 어디에 깔려 있나" (아직 CVE 가 안 붙은 시점)
- "openssl 버전이 서버마다 제각각인가"
- "이 서버에 뭐가 깔려 있나"

SBOM 관리의 절반이 여기다. N8 에서 만든다.
**최신 검사 것만 보관**하고 새 검사가 끝나면 교체한다(120,000 컴포넌트 × 검사 전부는 감당이 안 됨).

### 안 가져오는 것

| | 왜 |
|---|---|
| **Dashboard 를 첫 화면으로** | 숫자 카드 벽은 매일 쓰는 사람에게 한 번 보고 지나치는 장식이 된다. 첫 화면은 **자산 목록**이고, 급한 것은 목록 위 **한 줄**로 (§2.1) |
| **위험 점수** (심각도 가중합 한 숫자) | 줄 세우기엔 편하지만 grype 이 준 값이 아니다. "이 점수 근거가 뭐냐"에 답해야 하는 자리에서 불리하다. 기본 정렬은 **심각+높음 건수** — grype 이 준 값 그대로 |
| Dependency Graph | syft 가 주는 의존 관계가 대상마다 들쭉날쭉하다. 반쯤 맞는 그림은 없느니만 못하다 |
| 여러 분석기 · 판정 출처 표시 | 우리는 grype 하나다 |
| Teams · 권한 행렬 · LDAP/OIDC | 관리자·조회 둘로 충분하다 |
| 프로젝트 버전 · 부모-자식 | 우리 자산은 서버이지 버전 있는 애플리케이션이 아니다 |
| 알림(메일·웹훅) | 폐쇄망. 기한 경과는 화면 배지로 |
