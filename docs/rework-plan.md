# SBOMSight 개편 계획 (최종)

기능은 거의 다 있다. **무엇이 어디에 있어야 하는가를 잘못 정해 놓고 그 위에 화면을
그린 것**이 문제다. 지우고 옮기는 일이 대부분이고 새로 만드는 것은 적다.

미리보기: `docs/preview.html` — **여기서 승인된 것이 그대로 구현 사양이다.**

| 새로 드는 것 | 왜 |
|---|---|
| JDBC 드라이버 교체 | mysql-connector-j 는 GPL-2.0. MariaDB Connector/J 는 LGPL-2.1 (§11) |
| 마이그레이션 V11 | 판정(VEX) 어휘 (§4) |
| 마이그레이션 V12 | 마지막·그 전 로그인 (N6) |
| 마이그레이션 V13 | 패키지 인벤토리 (§3.3) |

| 2 | 구역 관리가 설정에 있다 | `설정 → 구역` 표 | 자산 화면으로 옮김 | N3 |

| 4 | 전사 조회 탭이 왜 있나 | `LookupController` 가 취약점 화면과 같은 질의를 부른다 | 탭 제거. 취약점 화면 하나로 | N2·N4 |

## 2. 정보 구조

### 지금 (기둥 7 + 구역 n)

```
자산 / 전사 조회 / 구역 보고서 / 조치 / 위험 수용 / 감사 로그 / 설정
─────────────────────────────
ZONE  DMZ · 내부업무 · 미분류 …
```

같은 것이 두 군데(구역·구역 보고서), 목록만 있고 입구가 없는 것(위험 수용),
자산의 거르개가 기둥에 올라온 것(ZONE), 관리자만 쓰는 것이 상시 노출(감사 로그).

### 바꿀 것 (기둥 6)

| 기둥 | 주소 | 무엇 | 흡수 |
|---|---|---|---|
| **자산** | `/` | 서버 목록 · 구역 묶음 · 구역 관리 | 구역 목록, 설정의 구역 표, 구역 현황 시안 |
| **취약점** | `/vulns` | 범위를 골라 보는 탐지 목록 · 판정 | 전사 조회, `/scans/{id}` |
| **패키지** | `/packages` | 무엇이 어디에 몇 버전으로 | 새로 생김 |
| **대응** | `/actions` | ① 조치 ② 판정 | 조치, 위험 수용 |
| **보고서** | `/reports` | 범위·기간을 골라 뽑는다 | 구역 보고서, `/report/{scanId}` |
| **설정** | `/settings` | 계정 · 접근 IP · 도구 · 감사 로그 | 감사 로그 |

기둥 아래: 계정 블록 → 메뉴(내 계정 / 비밀번호 변경 / 로그아웃).

> **기둥에 올릴 자격은 "자산을 거치지 않고 물을 수 있는 질문"이다.**
> "이 CVE 가 어디 있나", "openssl 이 어디 깔려 있나", "기한 지난 게 있나",
> "보고서 뽑자" 는 자격이 있다. "DMZ 서버 보여 줘" 는 자산의 거르개다.

## 3. 화면 명세

### 3.1 자산 `/`

```
자산                                  [구역 관리] [일괄 등록] [자산 등록]
검사 안 한 서버 2 · 30일 넘은 서버 1 · 기한 지난 조치 1 · 심각 16 · 수정본 없음 209
   ↑ 각 숫자가 링크다

[전체 9] [■DMZ 3] [■내부업무 3] [■관리망 2] [미분류 1]  보기:[표][구역] □보관된 자산도
```

- **요약 줄** 한 줄. 카드 벽을 만들지 않는다. 0 인 항목은 안 그린다.
- **구역 칩** 거르개. 선택은 URL(`?zone=3`)에 남는다.
- **표 보기** — 구역 머리줄 + 서버 행. 심각도는 **막대 하나**(§5-11). 헤더 클릭 정렬.
- **구역 보기** — 시안 카드 격자. 구역명 · 서버 수 · 기한 경과 배지 · 큰 수치(심각+높음) ·
  심각도 막대 · 심각도 건수 · **그 구역 서버 목록** · `가장 오래된 검사` · `⋮` 메뉴.
- **구역 관리** 팝업(추가·이름·색·삭제). `설정 → 구역` 은 삭제.
- **보관된 자산** — `Asset.archivedAt` 은 있는데 화면이 없다. 체크 하나로 보이고/숨고,
  자산 상세에 `보관` 버튼(삭제 말고 치우는 길).

### 3.2 취약점 `/vulns`

```
취약점                                                   [CSV 내려받기]
범위[전체▾]  묶기[항목별|CVE별|패키지별]
검색[        ] 심각도[▾] 수정본[▾] 실제악용[▾] 판정[▾] □감춘 것도    [찾기]
```

- **범위** `?zone=` · `?scan=` · 없으면 전체.
  **한 서버짜리는 여기 없다** — `/vulns?asset=12` 는 `/assets/12?tab=vulns` 로 넘긴다.
  표를 그리는 조각은 하나를 두 곳에서 쓴다.
- **묶기**

  | 모드 | 한 줄 | 열 |
  |---|---|---|
  | 항목별 | 탐지 1건 | 자산 · 취약점 · 심각도 · CVSS · 악용확률 · 패키지 · 설치→수정 · 판정 |
  | CVE별 | CVE 1건 | CVE · 심각도 · CVSS · **영향 서버 수** · **구역 분포** · 패키지 · 수정본 |
  | 패키지별 | 패키지 1건 | 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 영향 서버 수 |

- **행을 펼치면 판정 칸**(§4). 팝업이 아니라 제자리에서 — 목록을 잃지 않는다.
- **CVE 상세** `/vulns/{cve}` — CVSS 벡터 풀이 · 별칭(GHSA↔CVE) · **이 CVE 가 있는 서버 전부** ·
  판정 이력. 지금은 CVE 를 눌러도 갈 곳이 없다.
- 정렬에서 **값 없는 것은 방향과 무관하게 항상 뒤로.**

### 3.3 패키지 `/packages` — 새로 생김

**답해야 하는 질문**: 무엇이 어디에 몇 버전으로 깔려 있나 — **취약점이 붙기 전에도.**
지금은 `Scan.componentCount` 숫자 하나뿐이라 취약점이 붙은 패키지만 알 수 있다.
`log4j` 가 어디 있는지 CVE 가 터진 다음에야 찾게 된다.

```
패키지        유형  서버  버전 분포                                      취약점
openssl-libs  rpm   7대   ▮3.0.7-24 5대   ▮3.0.1-43 2대                     28
glibc         rpm   7대   ▮2.34-83 7대                                      49
python3       rpm   5대   ○3.9.18-1 4대   ○3.9.16-1 1대                     —
```

**취약한 버전을 눈으로 구분하는 법** (요구사항)

- 버전 앞 표시가 **그 버전에 걸린 최고 심각도 색** — `▮`심각 `▮`높음 `▮`보통 `▮`낮음.
- 취약점이 없는 버전은 **속 빈 표시 `○` + 회색**. 색만으로 가르지 않고 모양도 다르게 한다.
- 취약한 버전은 버전 글자도 그 색을 쓰고, 안전한 버전은 기본색 그대로.
- 표시에 마우스를 올리면 `심각 1 · 높음 6 · 보통 9`.
- **한 패키지 안에 취약한 버전과 안전한 버전이 섞여 있는 것이 가장 중요한 신호다** —
  "이미 올린 서버가 있는데 안 올린 서버가 남았다" 는 뜻이다. 이 줄은 표시를 따로 단다.
- 펼치면 서버별로: `web-01 · DMZ · 3.0.7-24 · 심각 0 · 높음 3 · 보통 5`.

거르개: 검색 · 구역 · 유형(rpm/deb/java-archive/python/…) · `취약점 있는 것만` ·
`버전이 갈린 것만`.

자산 상세의 `패키지` 탭도 같은 규칙(그 서버 것만, 설치 경로 포함).

**보관 범위** — 자산마다 **최신 완료 검사 것만** 두고 새 검사가 끝나면 교체한다.
컴포넌트 12만 개짜리 SBOM × 검사 전부를 쌓으면 감당이 안 된다.

### 3.4 대응 `/actions`

```
대응                                                     [CSV 내려받기]
[조치 12]  [판정 18]                        구역[▾] 서버[▾] 상태[▾]
```

- **조치 탭** — 기한 지난 것 위로.
- **판정 탭** — 다시 볼 날 지난 것 위로. 상태별 거르개.
- **등록은 여기서 하지 않는다. 취약점 화면에서 한다.** 이 화면은 결정을 모아 보는 자리다.

### 3.5 보고서 `/reports`

범위(서버/구역/전체) + 기준(최근 검사/기간)을 고르고 뽑는다. 최근에 만든 것 목록.

**문서 형식 — 기승전결 폐기**

```
             web-01 취약점 점검 결과 보고

문서 정보   점검 대상 / 점검 일시 / 점검 도구 / SBOM / 작성일 / 작성자

1. 점검 개요            표 — 컴포넌트 · 탐지 건수 · 고유 CVE · 영향 패키지 · 감춘 것
2. 점검 결과 요약       표 — 심각도별 건수·비중 / 수정 가능 여부 / 접근 경로
3. 조치 대상            표 — 순위 · 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 원격 접근
4. 수정본 없는 항목     표 — 패키지 · 건수 · 최고 심각도 · 판정 · 근거 · 다시 볼 날
5. 조치 진행 현황       표 — 패키지 · 상태 · 담당 · 기한
6. 이전 검사 대비       표 — 이전 / 신규 / 해소 / 유지 / 이번   (기간 보고서는 월별 추이)
[붙임] 전체 탐지 목록   표 (선택)
```

- **서술형 문단 0개.** `class="lead"` 문단, `기/승/전/결` 표시, 표 안의 "뜻" 칸 전부 제거.
  설명이 필요한 약어는 **표 아래 각주 한 줄**.
- **감춘 판정도 건수는 남긴다** — "탐지 187건 중 3건은 판정으로 감춤" 을 1장에 찍는다.
  감춰서 숫자가 줄어든 보고서는 점검에서 문제가 된다.
- 인쇄: A4 세로 · `thead { display: table-header-group }` · 장 사이 `page-break-before` · 쪽 번호.

### 3.6 설정 `/settings` (관리자)

탭 넷: **계정 · 접근 IP · 도구 · 감사 로그**.

- 계정 행마다 `[수정] [비밀번호 초기화] [삭제]`. **권한 드롭다운 즉시 저장 제거.**
  `수정` 팝업: 이름 · 권한 · 사용 여부 · **새 비밀번호(비우면 안 바꿈)** · 잠금 해제.
- 구역 표 삭제(자산 화면으로). 감사 로그는 여기 탭으로(기둥에서 뺀다).

### 3.7 계정 영역과 내 계정 `/me`

기둥 아래 계정 블록을 누르면 **메뉴**가 열린다 — 내 계정 / 비밀번호 변경 / 로그아웃.
`<details><summary>` 로 만든다(자바스크립트 없이 열리고 `Esc` 가 듣는다).

`/me` 는 카드 둘: **계정 정보**(계정·이름·권한·마지막 로그인·만든 날 + 이름 저장) ·
**비밀번호**(마지막 변경·주기 + 변경 버튼).

### 3.8 자산 상세 `/assets/{id}` — 탭으로 가른다

```
DMZ                                        ← 상위 라벨
web-01                       [보고서] [SBOM 올리기]
Rocky Linux 9.3 · 대외 웹 · 마지막 검사 2026-09-10 14:22
▮▮▮▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯ 187건
[개요] [취약점 187] [패키지 1,204] [검사 이력 12] [조치·판정 5]
```

| 탭 | 내용 |
|---|---|
| 개요 | 기본 정보 · 검사 진행 카드 · 보관/삭제 |
| 취약점 | `/vulns` 와 **같은 조각**으로 이 서버 것만 |
| 패키지 | 설치된 패키지 (§3.3 규칙 + 설치 경로) |
| 검사 이력 | 액션 `[열기] [다시 검사] [SBOM 내려받기] [삭제]` **전부 같은 버튼** |
| 조치·판정 | 이 서버의 조치와 판정 |

탭 선택은 URL 에(`?tab=vulns`). 탭 이름 옆 숫자는 0 이면 안 쓴다.

### 3.9 빈 화면

## 4. 어휘

### 4.0 규칙

1. **내가 지어낸 말을 쓰지 않는다.** 그 팀이 실제로 쓰는 말을 쓴다.
2. **한 가지를 가리키는 말은 하나만.** 지금 `서버`/`자산`, `컴포넌트`/`패키지`,
   `재검사`/`다시 검사` 가 섞여 있다.
3. **한 칸에 두 가지를 넣지 않는다.** `사유 · 대신하는 통제` 같은 열 머리를 두지 않는다.
4. **줄여서 뜻이 흐려지면 줄이지 않는다.** `바로 닿음`, `뜻`, `줄`, `한 일` 이 그 예다.

### 4.2 검토 결과 — 상태

**원칙: 저장값은 CycloneDX VEX 표준 그대로, 화면은 우리가 쓰는 말.**
내보내기·점검에서는 표준 이름으로 답하고, 쓰는 사람은 한국어를 읽는다.

| 저장값 | 화면 | 고르면 아래에 뜨는 한 줄 |
|---|---|---|
| `NOT_SET` | **미검토** | 아직 보지 않았습니다. |
| `IN_TRIAGE` | **검토 중** | 우리 환경에 해당되는지 확인하고 있습니다. |
| `EXPLOITABLE` | **해당됨** | 우리 환경에 영향이 있습니다. 고쳐야 합니다. |
| `NOT_AFFECTED` | **해당 없음** | 탐지는 맞지만 우리 환경에는 영향이 없습니다. **근거를 골라야 합니다.** |
| `FALSE_POSITIVE` | **오탐** | 탐지 자체가 틀렸습니다(패키지 오인 등). |

### 4.3 근거 — `해당 없음` 일 때만

| 저장값 | 화면 |
|---|---|
| `code_not_present` | 취약한 코드가 들어 있지 않음 |
| `code_not_reachable` | 취약한 코드를 실행하지 않음 |
| `requires_configuration` | 특정 설정을 켜야 하는데 안 켜 둠 |
| `requires_dependency` | 함께 있어야 할 다른 패키지가 없음 |
| `requires_environment` | 특정 환경에서만 되는데 그 환경이 아님 |
| `protected_by_compiler` | 컴파일 옵션이 막고 있음 |
| `protected_at_runtime` | 실행 환경이 막고 있음 |
| `protected_at_perimeter` | 방화벽·WAF 가 막고 있음 |
| `protected_by_mitigating_control` | 다른 통제가 막고 있음 |

### 4.4 대응 — 어떻게 할 것인가

**지적받은 자리다.** 직역해서 뜻이 안 통했다. 우리가 쓰는 말로 바꾼다.

| 저장값 | ~~앞서 쓴 말~~ | 바꿈 | 고르면 아래에 뜨는 한 줄 |
|---|---|---|---|
| `update` | ~~업데이트~~ | **버전 올려 조치** | 수정본이 나온 버전으로 올립니다. |
| `rollback` | ~~되돌리기~~ | **이전 버전으로 내림** | 올릴 수 없어, 취약하지 않은 예전 버전으로 내립니다. |
| `workaround_available` | ~~우회책 있음~~ | **우회 조치 (패치 없이)** | 설정 변경·접근 제한 등으로 막습니다. 패키지는 그대로 둡니다. |
| `can_not_fix` | ~~고칠 수 없음~~ | **조치 불가** | 수정본이 없고 우회도 되지 않습니다. |
| `will_not_fix` | ~~고치지 않음~~ | **조치 안 함 (위험 수용)** | 고칠 수 있지만 하지 않기로 하고 위험을 감수합니다. |

`조치 불가` 와 `조치 안 함` 의 차이는 **할 수 없는 것과 안 하기로 한 것**이다.
점검에서 묻는 것이 정확히 이 차이라 둘을 합치지 않는다.
`조치 안 함 (위험 수용)` 이 지금의 "위험 수용" 에 해당한다.

### 4.5 목록에서 빠지는 것 — 체크박스를 없앤다

앞서 `목록에서 감추기` 체크박스를 두려 했다. **없앤다.** 말도 이상하고, 사람이
켜고 끄게 두면 같은 상태인데 어떤 건 보이고 어떤 건 안 보인다.

**상태로 자동으로 정해진다.**

| 상태 | 기본 목록 |
|---|---|
| 미검토 · 검토 중 · 해당됨 | **보인다** — 아직 할 일이 남아 있다 |
| 해당 없음 · 오탐 | **빠진다** — 볼 일이 끝났다 |

거르개에 `검토 끝난 것도 보기` 하나만 둔다.
`해당됨 + 대응=조치 안 함(위험 수용)` 은 **계속 보인다** — 안 고치기로 한 것은
눈앞에 남아 있어야 한다.

**보고서에는 빠진 건수를 반드시 찍는다** — "탐지 187건 중 3건은 검토를 마쳐 목록에서
제외" (§3.5). 숫자가 조용히 줄어든 보고서는 점검에서 문제가 된다.

### 4.6 승인 — 지금 계획은 승인이 아니다

물어보신 그대로다. **`승인한 사람` 은 그냥 글자 칸이고, 아무나 아무 이름이나 적을 수
있다.** 승인 절차는 없다. 이름만 "승인" 인 칸은 점검에서 없느니만 못하다 —
통제가 있는 것처럼 보이는데 실제로는 없기 때문이다.

**바꿀 것 (권고)**

| 칸 | 어떻게 |
|---|---|
| **기록한 사람** | 입력칸 없음. **로그인한 계정이 자동으로** 박힌다 |
| **기록한 때** | 자동 |
| **결재 문서 번호** | 선택 입력. 사내 결재에서 난 승인의 참조 |
| **재검토일** | 입력 |
| 근거 · 다른 통제 · 메모 | 입력 |

**실제 승인은 사내 결재 시스템에서 난다.** 이 도구는 그 결재를 가리키는 번호만
갖는다. 시스템이 아는 값(누가 로그인해서 눌렀는가)은 자동으로 남기고, 모르는 값
(누가 결재했는가)은 **아는 척하지 않는다.**

**도구 안에 승인 흐름은 만들지 않는다 (결정됨).** 부서장이 이 화면에 매번 들어와
승인을 누르는 일은 실제로 일어나지 않는다. 승인은 사내 결재와 작업 결재에서 받고,
이 도구는 **그 번호를 적는 자리**로 끝낸다.

### 4.7 변경 이력

누가 언제 무엇을 어떻게 바꿨는지 한 줄씩 쌓인다. `RemediationEvent` 가 이미 같은
모양이라 그대로 따른다.

> **이것은 grype 의 판정을 바꾸는 것이 아니다.** grype 은 "이 패키지에 이 CVE 가
> 있다" 고 말했고 그 말은 그대로 남는다. 우리가 기록하는 것은 **그 말에 대한 우리의
> 결정**이다. 감춰도 보고서의 원본 건수는 줄지 않는다.

## 5. 공통 규칙

1. **행 액션은 전부 `btn small`.** 맨 링크와 버튼을 한 칸에 섞지 않는다.
   목록의 이름(자산명·패키지명)만 링크다.
2. 파괴적 동작은 `btn small danger` + 확인.
3. **거르개·정렬·쪽·탭은 URL 에.** 새로고침·공유·뒤로가기가 살아야 한다.
4. **없는 값은 `—`.** 0 이나 `false` 로 채우지 않는다.
5. 빈 화면에는 다음 버튼 하나. 설명 두 줄 넘기지 않는다.
6. 표 머리 클릭 정렬. **값 없는 행은 방향과 무관하게 뒤로.**
7. **문장을 화면에 쓰지 않는다.** 필요하면 `<details class="help">` 안으로.
8. 한 화면에 `<h2>` 넷을 넘기면 탭으로 가른다.
9. 숫자는 `num` 클래스(탭 정렬), 세 자리 쉼표.
10. 팝업은 `<dialog>`. 취소 왼쪽, 실행 오른쪽 `primary`.
11. **목록 행의 심각도는 막대 하나.** 0 아닌 구간은 **최소 2px** — 안 그러면 심각
    1건이 폭 0 으로 사라진다.
12. **페이지 머리는 한 모양**: 상위 라벨 → 제목 → 부제(값) → 오른쪽 버튼 묶음.
13. **표는 카드 안에.** 카드 머리에 제목과 그 표에만 걸리는 버튼.
14. **긴 표는 머리가 붙어 있는다** (`position: sticky`).
15. **색만으로 구분하지 않는다.** 색 옆에 언제나 글자나 모양이 함께 간다.
16. **누르면 갈 곳이 둘 이상이면 링크가 아니라 메뉴다.**
17. 자바스크립트 없이 되는 것은 자바스크립트로 하지 않는다 —
    메뉴는 `<details>`, 팝업은 `<dialog>`, 탭은 링크.
18. **고르는 항목에는 뜻 한 줄을 붙인다** (§4.2~4.4). 빈 칸은 사용법을 가르쳐 주지 않는다.
19. **지어낸 말을 쓰지 않는다.** 그 팀이 실제로 쓰는 말을 쓰고, 한 가지를 가리키는
    말은 하나만 쓴다. 줄여서 뜻이 흐려지면 줄이지 않는다. 새 화면 글자는 §4.1 을
    먼저 본다.
20. **시스템이 모르는 것을 아는 척하지 않는다.** 사람이 자유롭게 적는 칸에 통제를
    뜻하는 이름(`승인한 사람`)을 붙이지 않는다 (§4.6).

## 7. DB 와 의존성

### 드라이버 교체 (N1)

| | 지금 | 바꿈 |
|---|---|---|
| 드라이버 | `com.mysql:mysql-connector-j` — **GPL-2.0** + FOSS Exception | `org.mariadb.jdbc:mariadb-java-client` — **LGPL-2.1-or-later** |
| URL | `jdbc:mysql://…` | `jdbc:mariadb://…` |
| 드라이버 클래스 | `com.mysql.cj.jdbc.Driver` | `org.mariadb.jdbc.Driver` |

- MariaDB Connector/J 는 **MariaDB 와 MySQL 둘 다** 붙는다.
  MySQL 8 의 기본 인증(`caching_sha2_password`)은 **2.5.0 부터 지원**한다(현재 3.5.x).
- URL 매개변수가 다르다: `useSSL=false` → `sslMode=disable`,
  `serverTimezone=` → 서버 시간대 설정, `allowPublicKeyRetrieval` 불필요.
  `rewriteBatchedStatements=true` 는 그대로 있다(배치 저장에 필요).
- Flyway 는 `flyway-mysql` 모듈이 MariaDB 도 덮는다. Hibernate 방언은 자동 판별되며,
  어긋나면 명시한다.
- **서버도 MariaDB 로 바꾸는 것을 함께 검토한다.** 이미 `check-mariadb.sh` 가
  MariaDB 10.11 로 전체 시험을 돌리고 있다 — 바꾸면 **시험하는 것과 운영하는 것이
  같아진다.** MySQL 8 을 그대로 둬도 위 드라이버로 동작한다.
  (DB 서버는 별개 프로그램이라 라이선스가 우리 코드에 옮지 않는다. 드라이버만이 문제다.)

### V11 — 판정 (N5)

```
finding_analysis        (asset_id, cve, package_name, state, justification,
                         response, note, other_control, approval_doc, review_by,
                         created_at, updated_at, updated_by)
                        UNIQUE (asset_id, cve, package_name)
```

기존 `risk_acceptances` 행을 **`상태=해당됨 · 대응=조치 안 함(위험 수용)`** 으로
옮기고 표를 지운다. 뜻이 그대로 보존된다.

**초안에서 두 가지를 고쳤다.**

- `hidden` 열을 두지 않는다. §4.5 에서 감추기 칸 자체를 없애고 **상태가
  정하도록** 바꿨다. 열을 두면 상태와 감춤이 어긋날 수 있고, 어긋나면 어느
  쪽이 맞는지 아무도 모른다.
- `approved_by` → `approval_doc`. §4.6 의 결정을 열 이름까지 반영한다.

**옮기지 못하는 것은 뜻을 바꿔 옮기지 않는다.** 철회된 수용은 '지금의 결정' 이
아니므로 `미검토` 로 두고, 수용했다가 거뒀다는 사실은 **변경 이력에** 그때 시각
그대로 남긴다. 같은 키에 철회분이 여럿이면 가장 나중 것 하나만 행이 된다.

**띄워 보고 찾은 것** (시험 227개가 전부 통과한 채로 있던 것):

적어 둔 검토 결과가 **취약점 목록에 안 붙었다.** 키를 `finding.cve`(grype 의 주
식별자)로 잡았는데, grype 이 GHSA 를 주 식별자로 낸 건은 사람이 읽고 적는 것이
함께 온 CVE 번호다. 그래서 같은 건을 적어 놓고도 목록에는 "아직 안 적음" 으로
떴다. 화면에 찍는 번호로 키를 잡고, 옛 번호로 적힌 것(옮겨 온 행)도 찾도록
두 번호를 모두 본다.

그 시험을 처음엔 `html.contains("해당 없음")` 으로 썼다가 **고치기 전 코드에서도
통과했다** — 같은 화면에 있는 대화상자에 다섯 상태가 전부 들어 있어서 언제나
걸렸다. 행이 그린 것만 보도록 고쳤다.

**어휘 — §4.1 과 §4.3 이 `근거` 를 두 가지에 쓰고 있었다**

자유 입력 칸(`사유`→`근거`)과 `해당 없음` 일 때 고르는 표준값. §4.0 규칙 2 와
충돌한다. **고르는 것을 `근거`, 적는 것을 `설명`** 으로 갈랐다.

### N5b — `/actions` 두 탭 ✅
- 새 `ActionController`(`/actions`) — `조치` 와 `검토 결과` 두 탭.

  MySQL 에서는 기한을 아직 안 정한 것(NULL)이 맨 앞에 온다 — 가장 급한 자리에

  `remediation-detail.html` → `action-detail.html`

  → `/actions`(그 탭), `/remediations/{id}` → `/actions/{id}`
- 등록하는 길은 그대로 취약점 화면에 둔다. 두 컨트롤러에 POST 하나씩만 남겼다 —
  **목록만 보고 무엇을 조치할지 고를 수는 없다**
- 자산 상세의 `조치·검토` 탭에 **검토 결과를 넣었다.** 탭 이름은 그런데 조치만
  있었고, 검토 결과는 대응 화면에서만 볼 수 있어 "이 서버 것만" 을 물을 자리가
  없었다 (§1 지적 7)

**어휘 — 없는 승인이 하나 더 있었다.** `RemediationStatus.ACCEPTED` 의 화면
이름이 `예외 승인` 이었다. 아무나 눌러 닫을 수 있는 상태에 '승인' 을 붙이면
통제가 있는 것처럼 보이는데 실제로는 없다. `하지 않고 닫음` 으로 고쳤다.

> **남은 겹침 — 결정이 필요하다.** "안 고치기로 했다" 는 판단은 이제 검토
> 결과의 대응(`조치 안 함`)이 담는다. 조치 상태의 `ACCEPTED` 는 *그 판단이
> 아니라 조치 하나가 닫힌 상태*인데, 둘이 가까워서 어느 쪽을 봐야 할지
> 헷갈릴 수 있다. 없애고 검토 결과로 모으려면 값이 DB 에 글자로 들어 있어
> 마이그레이션이 필요하다 — 화면을 합치는 단계에서 함께 하지 않았다.

### N6 — 계정 ⚠ V12 ✅
- `AccountService.update(username, displayName, role, enabled, newPasswordOrNull, actor)`
  — `changeRole` 과 `setEnabled` 를 여기로 합쳤다. 권한을 바꾸는 길이 둘이면
  한쪽에만 '마지막 관리자' 보호가 걸린 채로 남는 날이 온다
- 새 `MeController`(`/me`), `me.html` 카드 둘. `/me` 임시 다리 제거
- `settings.html` 계정 `[수정]` 팝업. **권한 드롭다운 즉시 저장 제거** —
  실수로 스친 것과 정말 바꾼 것을 가르지 못했고 되돌릴 자리도 없었다
- `AuditEvent.USER_UPDATED`
- 비밀번호 칸은 **비우면 안 건드린다.** 정해 주면 본인이 받아서 곧바로 다시
  바꾸게 한다(`mustChange`) — 관리자가 아는 비밀번호를 그대로 쓰게 두지 않는다

**`users.last_login_at` 이 한 번도 채워지지 않았다** (N1 에서 발견). 열은 V1
부터 있었고 화면 둘이 그 값을 읽고 있었는데 `setLastLoginAt` 을 부르는 곳이
코드 어디에도 없었다.

> **그런데 로그인할 때 채우기만 하면 반대로 뒤집힌다.** 비밀번호 변경 화면은
> `lastLoginAt == null` 로 "최초 로그인" 과 "관리자가 초기화함" 을 갈랐는데,
> 그 화면은 로그인 **다음 요청**에서 뜬다 — 이미 이번 로그인 시각이 박혀 있어
> 이번에는 전부 '임시 비밀번호' 가 된다. 순서로는 풀리지 않는다.

**V12 — 사실 두 개를 두 칸에 나눠 적는다.**

```
last_login_at      이번에 들어온 시각     → 설정의 '마지막 로그인'
previous_login_at  그 전에 들어온 시각    → NULL 이면 이번이 처음
```

날짜 하나로 눈치껏 가르려 하면(만든 시각과 비교한다든지) 언젠가 틀리고
틀린 줄도 모른다. 이미 쓰던 설치는 **감사 로그의 로그인 성공 기록으로
채운다** — 지어내는 것이 아니라 우리가 이미 가지고 있는 값이다.

`LoginAttemptService.onSuccess` 가 `recordLogin(now)` 으로 한 칸 민다.
두 칸을 따로 세팅하게 두지 않는다 — 한쪽만 건드리면 '그 전 로그인' 이
이번 로그인과 같아지거나 영영 비어 있게 된다.

> **마이그레이션 번호가 하나 밀렸다.** 패키지 인벤토리(N9)는 V12 → **V13**.

시험은 `LoginFlowTest` 에 둔다 — **실제 필터 체인으로** 로그인해야 이 자리를
지나간다. `.with(user(...))` 로 주체를 꽂는 시험은 이 버그를 잡지 못했고,
실제로 시험 229개가 전부 통과한 채로 망가져 있었다.

## 10. 참고한 것

같은 일을 하는 공개 도구의 **화면 구성**만 참고한다. 판정 엔진은 참고하지 않는다 —
우리는 grype 하나를 믿기로 했고 그쪽은 여러 분석기를 합친다.

| Tabler | 페이지 머리 · 탭 · 카드 · 빈 화면 · 계정 메뉴 **구조** | 화면마다 제각각이던 것을 한 모양으로 |
