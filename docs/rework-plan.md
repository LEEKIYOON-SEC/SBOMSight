# SBOMSight 개편 계획 (최종)

기능은 거의 다 있다. **무엇이 어디에 있어야 하는가를 잘못 정해 놓고 그 위에 화면을
그린 것**이 문제다. 지우고 옮기는 일이 대부분이고 새로 만드는 것은 적다.

미리보기: `docs/preview.html` — **여기서 승인된 것이 그대로 구현 사양이다.**

| 새로 드는 것 | 왜 |
|---|---|
| JDBC 드라이버 교체 | mysql-connector-j 는 GPL-2.0. MariaDB Connector/J 는 LGPL-2.1 (§11) |
| 마이그레이션 V11 | 판정(VEX) 어휘 (§4) |
| 마이그레이션 V12 | 마지막·그 전 로그인 (N6) |

## 1. 지적받은 것 → 무엇을 하는가

| # | 지적 | 지금 | 조치 | 단계 |
|---|---|---|---|---|
| 1 | 구역이 기둥에 서 있는데 눌러도 결국 자산으로 간다 | `layout.html:62` 의 구역 링크는 `/?zone=N` — 자산 목록에 거르개 하나 건 것 | 기둥에서 구역 목록 제거. 자산 화면 안의 묶음·거르개로 | N2·N3 |
| 2 | 구역 관리가 설정에 있다 | `설정 → 구역` 표 | 자산 화면으로 옮김 | N3 |
| 3 | 구역 현황 시안이 없다 | 없음 | 별도 화면 아님. **자산의 `구역 보기`** — 카드 안에 서버가 들어 있어 튕기지 않는다 | N3 |
| 4 | 전사 조회 탭이 왜 있나 | `LookupController` 가 취약점 화면과 같은 질의를 부른다 | 탭 제거. 취약점 화면 하나로 | N2·N4 |
| 5 | 구역별·취약점별로 한 번에 보고 싶다 | 없음 | 묶어 보기: 항목별 / CVE별 / 패키지별 | N4 |
| 6 | 위험 수용이 뭔지 어떻게 쓰는지 모르겠다 | 목록에 **철회 버튼만** 있다. 등록 팝업은 `/scans/{id}` 안에 맨 링크로 숨어 있고 사유는 **빈 칸**이다 | 탭 제거. 취약점 행에서 판정. **빈 칸 대신 고르는 항목** (§4) | N2·N5 |
| 7 | 위험 수용·조치는 서버별·구역별로 봐야 한다 | 전역 목록만 | 자산 상세에 그 서버의 것. 대응 화면에 거르개 | N5 |
| 8 | 검사 이력의 `열기` 가 글자인데 옆은 버튼 | `asset-detail.html:132` | 행 액션은 전부 같은 버튼 (§5) | N3·N8 |
| 9 | admin 을 누르면 비밀번호 변경으로 간다 | `layout.html:78` → `/password` | 갈 곳이 셋이면 링크가 아니라 **메뉴**. `/me` 신설 | N6 |
| 10 | 계정에 초기화는 있는데 수정이 없다 | 권한 드롭다운이 바꾸는 즉시 저장. 이름·비밀번호는 못 바꿈 | `수정` 팝업 | N6 |
| 11 | 보고서가 누가 봐도 AI 가 쓴 것 같다 | `기·승·전·결` 4장, 장마다 서술형 `class="lead"` 문단 | 기승전결 폐기. 점검 결과 보고서 형식. **서술형 문장 금지** | N7 |
| 12 | 무엇이 어디에 깔려 있는지 모른다 | `Scan.componentCount` 숫자 하나뿐 | 패키지 인벤토리 신설 (§3.3) | N9 |
| 13 | 판정 어휘가 이상하다 (되돌리기? 우회책 있음?) | — | 저장값은 표준, **화면은 우리 말** (§4) | N5 |
| 14 | 라이선스 | mysql-connector-j 가 GPL-2.0 | MariaDB Connector/J (LGPL-2.1) 로 교체 | N1 |
| 15 | 어휘가 자연스럽지 못하다 (`다시 볼 날`? `감춤`?) | `바로 닿음` `뜻` `줄` `한 일` `사유 · 대신하는 통제` 등 지어낸 말이 화면에 그대로 있다. `서버`/`자산`, `컴포넌트`/`패키지` 가 섞여 있다 | **전체 훑어 표로 못 박음** (§4.1). `감춤` 은 체크박스째 없앰 (§4.5) | N2~N8 |

## 2. 정보 구조

### 지금 (기둥 7 + 구역 n)

```
자산 / 전사 조회 / 구역 보고서 / 조치 / 위험 수용 / 감사 로그 / 설정
─────────────────────────────
ZONE  DMZ · 내부업무 · 미분류 …
```

같은 것이 두 군데(구역·구역 보고서), 목록만 있고 입구가 없는 것(위험 수용),
자산의 거르개가 기둥에 올라온 것(ZONE), 관리자만 쓰는 것이 상시 노출(감사 로그).

### 바꿀 것 (기둥 6)

| 기둥 | 주소 | 무엇 | 흡수 |
|---|---|---|---|
| **자산** | `/` | 서버 목록 · 구역 묶음 · 구역 관리 | 구역 목록, 설정의 구역 표, 구역 현황 시안 |
| **취약점** | `/vulns` | 범위를 골라 보는 탐지 목록 · 판정 | 전사 조회, `/scans/{id}` |
| **패키지** | `/packages` | 무엇이 어디에 몇 버전으로 | 새로 생김 |
| **대응** | `/actions` | ① 조치 ② 판정 | 조치, 위험 수용 |
| **보고서** | `/reports` | 범위·기간을 골라 뽑는다 | 구역 보고서, `/report/{scanId}` |
| **설정** | `/settings` | 계정 · 접근 IP · 도구 · 감사 로그 | 감사 로그 |

기둥 아래: 계정 블록 → 메뉴(내 계정 / 비밀번호 변경 / 로그아웃).

> **기둥에 올릴 자격은 "자산을 거치지 않고 물을 수 있는 질문"이다.**
> "이 CVE 가 어디 있나", "openssl 이 어디 깔려 있나", "기한 지난 게 있나",
> "보고서 뽑자" 는 자격이 있다. "DMZ 서버 보여 줘" 는 자산의 거르개다.

## 3. 화면 명세

### 3.1 자산 `/`

```
자산                                  [구역 관리] [일괄 등록] [자산 등록]
검사 안 한 서버 2 · 30일 넘은 서버 1 · 기한 지난 조치 1 · 심각 16 · 수정본 없음 209
   ↑ 각 숫자가 링크다

[전체 9] [■DMZ 3] [■내부업무 3] [■관리망 2] [미분류 1]  보기:[표][구역] □보관된 자산도
```

- **요약 줄** 한 줄. 카드 벽을 만들지 않는다. 0 인 항목은 안 그린다.
- **구역 칩** 거르개. 선택은 URL(`?zone=3`)에 남는다.
- **표 보기** — 구역 머리줄 + 서버 행. 심각도는 **막대 하나**(§5-11). 헤더 클릭 정렬.
- **구역 보기** — 시안 카드 격자. 구역명 · 서버 수 · 기한 경과 배지 · 큰 수치(심각+높음) ·
  심각도 막대 · 심각도 건수 · **그 구역 서버 목록** · `가장 오래된 검사` · `⋮` 메뉴.
- **구역 관리** 팝업(추가·이름·색·삭제). `설정 → 구역` 은 삭제.
- **보관된 자산** — `Asset.archivedAt` 은 있는데 화면이 없다. 체크 하나로 보이고/숨고,
  자산 상세에 `보관` 버튼(삭제 말고 치우는 길).

### 3.2 취약점 `/vulns`

```
취약점                                                   [CSV 내려받기]
범위[전체▾]  묶기[항목별|CVE별|패키지별]
검색[        ] 심각도[▾] 수정본[▾] 실제악용[▾] 판정[▾] □감춘 것도    [찾기]
```

- **범위** `?zone=` · `?scan=` · 없으면 전체.
  **한 서버짜리는 여기 없다** — `/vulns?asset=12` 는 `/assets/12?tab=vulns` 로 넘긴다.
  표를 그리는 조각은 하나를 두 곳에서 쓴다.
- **묶기**

  | 모드 | 한 줄 | 열 |
  |---|---|---|
  | 항목별 | 탐지 1건 | 자산 · 취약점 · 심각도 · CVSS · 악용확률 · 패키지 · 설치→수정 · 판정 |
  | CVE별 | CVE 1건 | CVE · 심각도 · CVSS · **영향 서버 수** · **구역 분포** · 패키지 · 수정본 |
  | 패키지별 | 패키지 1건 | 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 영향 서버 수 |

- **행을 펼치면 판정 칸**(§4). 팝업이 아니라 제자리에서 — 목록을 잃지 않는다.
- **CVE 상세** `/vulns/{cve}` — CVSS 벡터 풀이 · 별칭(GHSA↔CVE) · **이 CVE 가 있는 서버 전부** ·
  판정 이력. 지금은 CVE 를 눌러도 갈 곳이 없다.
- 정렬에서 **값 없는 것은 방향과 무관하게 항상 뒤로.**

### 3.3 패키지 `/packages` — 새로 생김

**답해야 하는 질문**: 무엇이 어디에 몇 버전으로 깔려 있나 — **취약점이 붙기 전에도.**
지금은 `Scan.componentCount` 숫자 하나뿐이라 취약점이 붙은 패키지만 알 수 있다.
`log4j` 가 어디 있는지 CVE 가 터진 다음에야 찾게 된다.

```
패키지        유형  서버  버전 분포                                      취약점
openssl-libs  rpm   7대   ▮3.0.7-24 5대   ▮3.0.1-43 2대                     28
glibc         rpm   7대   ▮2.34-83 7대                                      49
python3       rpm   5대   ○3.9.18-1 4대   ○3.9.16-1 1대                     —
```

**취약한 버전을 눈으로 구분하는 법** (요구사항)

- 버전 앞 표시가 **그 버전에 걸린 최고 심각도 색** — `▮`심각 `▮`높음 `▮`보통 `▮`낮음.
- 취약점이 없는 버전은 **속 빈 표시 `○` + 회색**. 색만으로 가르지 않고 모양도 다르게 한다.
- 취약한 버전은 버전 글자도 그 색을 쓰고, 안전한 버전은 기본색 그대로.
- 표시에 마우스를 올리면 `심각 1 · 높음 6 · 보통 9`.
- **한 패키지 안에 취약한 버전과 안전한 버전이 섞여 있는 것이 가장 중요한 신호다** —
  "이미 올린 서버가 있는데 안 올린 서버가 남았다" 는 뜻이다. 이 줄은 표시를 따로 단다.
- 펼치면 서버별로: `web-01 · DMZ · 3.0.7-24 · 심각 0 · 높음 3 · 보통 5`.

거르개: 검색 · 구역 · 유형(rpm/deb/java-archive/python/…) · `취약점 있는 것만` ·
`버전이 갈린 것만`.

자산 상세의 `패키지` 탭도 같은 규칙(그 서버 것만, 설치 경로 포함).

**보관 범위** — 자산마다 **최신 완료 검사 것만** 두고 새 검사가 끝나면 교체한다.
컴포넌트 12만 개짜리 SBOM × 검사 전부를 쌓으면 감당이 안 된다.

### 3.4 대응 `/actions`

```
대응                                                     [CSV 내려받기]
[조치 12]  [판정 18]                        구역[▾] 서버[▾] 상태[▾]
```

- **조치 탭** — 기한 지난 것 위로.
- **판정 탭** — 다시 볼 날 지난 것 위로. 상태별 거르개.
- **등록은 여기서 하지 않는다. 취약점 화면에서 한다.** 이 화면은 결정을 모아 보는 자리다.

### 3.5 보고서 `/reports`

범위(서버/구역/전체) + 기준(최근 검사/기간)을 고르고 뽑는다. 최근에 만든 것 목록.

**문서 형식 — 기승전결 폐기**

```
             web-01 취약점 점검 결과 보고

문서 정보   점검 대상 / 점검 일시 / 점검 도구 / SBOM / 작성일 / 작성자

1. 점검 개요            표 — 컴포넌트 · 탐지 건수 · 고유 CVE · 영향 패키지 · 감춘 것
2. 점검 결과 요약       표 — 심각도별 건수·비중 / 수정 가능 여부 / 접근 경로
3. 조치 대상            표 — 순위 · 패키지 · 현재→목표 · 해소 건수 · 최고 심각도 · 원격 접근
4. 수정본 없는 항목     표 — 패키지 · 건수 · 최고 심각도 · 판정 · 근거 · 다시 볼 날
5. 조치 진행 현황       표 — 패키지 · 상태 · 담당 · 기한
6. 이전 검사 대비       표 — 이전 / 신규 / 해소 / 유지 / 이번   (기간 보고서는 월별 추이)
[붙임] 전체 탐지 목록   표 (선택)
```

- **서술형 문단 0개.** `class="lead"` 문단, `기/승/전/결` 표시, 표 안의 "뜻" 칸 전부 제거.
  설명이 필요한 약어는 **표 아래 각주 한 줄**.
- **감춘 판정도 건수는 남긴다** — "탐지 187건 중 3건은 판정으로 감춤" 을 1장에 찍는다.
  감춰서 숫자가 줄어든 보고서는 점검에서 문제가 된다.
- 인쇄: A4 세로 · `thead { display: table-header-group }` · 장 사이 `page-break-before` · 쪽 번호.

### 3.6 설정 `/settings` (관리자)

탭 넷: **계정 · 접근 IP · 도구 · 감사 로그**.

- 계정 행마다 `[수정] [비밀번호 초기화] [삭제]`. **권한 드롭다운 즉시 저장 제거.**
  `수정` 팝업: 이름 · 권한 · 사용 여부 · **새 비밀번호(비우면 안 바꿈)** · 잠금 해제.
- 구역 표 삭제(자산 화면으로). 감사 로그는 여기 탭으로(기둥에서 뺀다).

### 3.7 계정 영역과 내 계정 `/me`

기둥 아래 계정 블록을 누르면 **메뉴**가 열린다 — 내 계정 / 비밀번호 변경 / 로그아웃.
`<details><summary>` 로 만든다(자바스크립트 없이 열리고 `Esc` 가 듣는다).

`/me` 는 카드 둘: **계정 정보**(계정·이름·권한·마지막 로그인·만든 날 + 이름 저장) ·
**비밀번호**(마지막 변경·주기 + 변경 버튼).

### 3.8 자산 상세 `/assets/{id}` — 탭으로 가른다

```
DMZ                                        ← 상위 라벨
web-01                       [보고서] [SBOM 올리기]
Rocky Linux 9.3 · 대외 웹 · 마지막 검사 2026-09-10 14:22
▮▮▮▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯ 187건
[개요] [취약점 187] [패키지 1,204] [검사 이력 12] [조치·판정 5]
```

| 탭 | 내용 |
|---|---|
| 개요 | 기본 정보 · 검사 진행 카드 · 보관/삭제 |
| 취약점 | `/vulns` 와 **같은 조각**으로 이 서버 것만 |
| 패키지 | 설치된 패키지 (§3.3 규칙 + 설치 경로) |
| 검사 이력 | 액션 `[열기] [다시 검사] [SBOM 내려받기] [삭제]` **전부 같은 버튼** |
| 조치·판정 | 이 서버의 조치와 판정 |

탭 선택은 URL 에(`?tab=vulns`). 탭 이름 옆 숫자는 0 이면 안 쓴다.

## 4. 어휘

### 4.0 규칙

1. **내가 지어낸 말을 쓰지 않는다.** 그 팀이 실제로 쓰는 말을 쓴다.
2. **한 가지를 가리키는 말은 하나만.** 지금 `서버`/`자산`, `컴포넌트`/`패키지`,
   `재검사`/`다시 검사` 가 섞여 있다.
3. **한 칸에 두 가지를 넣지 않는다.** `사유 · 대신하는 통제` 같은 열 머리를 두지 않는다.
4. **줄여서 뜻이 흐려지면 줄이지 않는다.** `바로 닿음`, `뜻`, `줄`, `한 일` 이 그 예다.

### 4.2 검토 결과 — 상태

**원칙: 저장값은 CycloneDX VEX 표준 그대로, 화면은 우리가 쓰는 말.**
내보내기·점검에서는 표준 이름으로 답하고, 쓰는 사람은 한국어를 읽는다.

| 저장값 | 화면 | 고르면 아래에 뜨는 한 줄 |
|---|---|---|
| `NOT_SET` | **미검토** | 아직 보지 않았습니다. |
| `IN_TRIAGE` | **검토 중** | 우리 환경에 해당되는지 확인하고 있습니다. |
| `EXPLOITABLE` | **해당됨** | 우리 환경에 영향이 있습니다. 고쳐야 합니다. |
| `NOT_AFFECTED` | **해당 없음** | 탐지는 맞지만 우리 환경에는 영향이 없습니다. **근거를 골라야 합니다.** |
| `FALSE_POSITIVE` | **오탐** | 탐지 자체가 틀렸습니다(패키지 오인 등). |

### 4.3 근거 — `해당 없음` 일 때만

| 저장값 | 화면 |
|---|---|
| `code_not_present` | 취약한 코드가 들어 있지 않음 |
| `code_not_reachable` | 취약한 코드를 실행하지 않음 |
| `requires_configuration` | 특정 설정을 켜야 하는데 안 켜 둠 |
| `requires_dependency` | 함께 있어야 할 다른 패키지가 없음 |
| `requires_environment` | 특정 환경에서만 되는데 그 환경이 아님 |
| `protected_by_compiler` | 컴파일 옵션이 막고 있음 |
| `protected_at_runtime` | 실행 환경이 막고 있음 |
| `protected_at_perimeter` | 방화벽·WAF 가 막고 있음 |
| `protected_by_mitigating_control` | 다른 통제가 막고 있음 |

### 4.4 대응 — 어떻게 할 것인가

**지적받은 자리다.** 직역해서 뜻이 안 통했다. 우리가 쓰는 말로 바꾼다.

| 저장값 | ~~앞서 쓴 말~~ | 바꿈 | 고르면 아래에 뜨는 한 줄 |
|---|---|---|---|
| `update` | ~~업데이트~~ | **버전 올려 조치** | 수정본이 나온 버전으로 올립니다. |
| `rollback` | ~~되돌리기~~ | **이전 버전으로 내림** | 올릴 수 없어, 취약하지 않은 예전 버전으로 내립니다. |
| `workaround_available` | ~~우회책 있음~~ | **우회 조치 (패치 없이)** | 설정 변경·접근 제한 등으로 막습니다. 패키지는 그대로 둡니다. |
| `can_not_fix` | ~~고칠 수 없음~~ | **조치 불가** | 수정본이 없고 우회도 되지 않습니다. |
| `will_not_fix` | ~~고치지 않음~~ | **조치 안 함 (위험 수용)** | 고칠 수 있지만 하지 않기로 하고 위험을 감수합니다. |

`조치 불가` 와 `조치 안 함` 의 차이는 **할 수 없는 것과 안 하기로 한 것**이다.
점검에서 묻는 것이 정확히 이 차이라 둘을 합치지 않는다.
`조치 안 함 (위험 수용)` 이 지금의 "위험 수용" 에 해당한다.

### 4.5 목록에서 빠지는 것 — 체크박스를 없앤다

앞서 `목록에서 감추기` 체크박스를 두려 했다. **없앤다.** 말도 이상하고, 사람이
켜고 끄게 두면 같은 상태인데 어떤 건 보이고 어떤 건 안 보인다.

**상태로 자동으로 정해진다.**

| 상태 | 기본 목록 |
|---|---|
| 미검토 · 검토 중 · 해당됨 | **보인다** — 아직 할 일이 남아 있다 |
| 해당 없음 · 오탐 | **빠진다** — 볼 일이 끝났다 |

거르개에 `검토 끝난 것도 보기` 하나만 둔다.
`해당됨 + 대응=조치 안 함(위험 수용)` 은 **계속 보인다** — 안 고치기로 한 것은
눈앞에 남아 있어야 한다.

**보고서에는 빠진 건수를 반드시 찍는다** — "탐지 187건 중 3건은 검토를 마쳐 목록에서
제외" (§3.5). 숫자가 조용히 줄어든 보고서는 점검에서 문제가 된다.

### 4.6 승인 — 지금 계획은 승인이 아니다

물어보신 그대로다. **`승인한 사람` 은 그냥 글자 칸이고, 아무나 아무 이름이나 적을 수
있다.** 승인 절차는 없다. 이름만 "승인" 인 칸은 점검에서 없느니만 못하다 —
통제가 있는 것처럼 보이는데 실제로는 없기 때문이다.

**바꿀 것 (권고)**

| 칸 | 어떻게 |
|---|---|
| **기록한 사람** | 입력칸 없음. **로그인한 계정이 자동으로** 박힌다 |
| **기록한 때** | 자동 |
| **결재 문서 번호** | 선택 입력. 사내 결재에서 난 승인의 참조 |
| **재검토일** | 입력 |
| 근거 · 다른 통제 · 메모 | 입력 |

**실제 승인은 사내 결재 시스템에서 난다.** 이 도구는 그 결재를 가리키는 번호만
갖는다. 시스템이 아는 값(누가 로그인해서 눌렀는가)은 자동으로 남기고, 모르는 값
(누가 결재했는가)은 **아는 척하지 않는다.**

**도구 안에 승인 흐름은 만들지 않는다 (결정됨).** 부서장이 이 화면에 매번 들어와
승인을 누르는 일은 실제로 일어나지 않는다. 승인은 사내 결재와 작업 결재에서 받고,
이 도구는 **그 번호를 적는 자리**로 끝낸다.

### 4.7 변경 이력

누가 언제 무엇을 어떻게 바꿨는지 한 줄씩 쌓인다. `RemediationEvent` 가 이미 같은
모양이라 그대로 따른다.

> **이것은 grype 의 판정을 바꾸는 것이 아니다.** grype 은 "이 패키지에 이 CVE 가
> 있다" 고 말했고 그 말은 그대로 남는다. 우리가 기록하는 것은 **그 말에 대한 우리의
> 결정**이다. 감춰도 보고서의 원본 건수는 줄지 않는다.

## 5. 공통 규칙

1. **행 액션은 전부 `btn small`.** 맨 링크와 버튼을 한 칸에 섞지 않는다.
   목록의 이름(자산명·패키지명)만 링크다.
2. 파괴적 동작은 `btn small danger` + 확인.
3. **거르개·정렬·쪽·탭은 URL 에.** 새로고침·공유·뒤로가기가 살아야 한다.
4. **없는 값은 `—`.** 0 이나 `false` 로 채우지 않는다.
5. 빈 화면에는 다음 버튼 하나. 설명 두 줄 넘기지 않는다.
6. 표 머리 클릭 정렬. **값 없는 행은 방향과 무관하게 뒤로.**
7. **문장을 화면에 쓰지 않는다.** 필요하면 `<details class="help">` 안으로.
8. 한 화면에 `<h2>` 넷을 넘기면 탭으로 가른다.
9. 숫자는 `num` 클래스(탭 정렬), 세 자리 쉼표.
10. 팝업은 `<dialog>`. 취소 왼쪽, 실행 오른쪽 `primary`.
11. **목록 행의 심각도는 막대 하나.** 0 아닌 구간은 **최소 2px** — 안 그러면 심각
    1건이 폭 0 으로 사라진다.
12. **페이지 머리는 한 모양**: 상위 라벨 → 제목 → 부제(값) → 오른쪽 버튼 묶음.
13. **표는 카드 안에.** 카드 머리에 제목과 그 표에만 걸리는 버튼.
14. **긴 표는 머리가 붙어 있는다** (`position: sticky`).
15. **색만으로 구분하지 않는다.** 색 옆에 언제나 글자나 모양이 함께 간다.
16. **누르면 갈 곳이 둘 이상이면 링크가 아니라 메뉴다.**
17. 자바스크립트 없이 되는 것은 자바스크립트로 하지 않는다 —
    메뉴는 `<details>`, 팝업은 `<dialog>`, 탭은 링크.
18. **고르는 항목에는 뜻 한 줄을 붙인다** (§4.2~4.4). 빈 칸은 사용법을 가르쳐 주지 않는다.
19. **지어낸 말을 쓰지 않는다.** 그 팀이 실제로 쓰는 말을 쓰고, 한 가지를 가리키는
    말은 하나만 쓴다. 줄여서 뜻이 흐려지면 줄이지 않는다. 새 화면 글자는 §4.1 을
    먼저 본다.
20. **시스템이 모르는 것을 아는 척하지 않는다.** 사람이 자유롭게 적는 칸에 통제를
    뜻하는 이름(`승인한 사람`)을 붙이지 않는다 (§4.6).

## 7. DB 와 의존성

### 드라이버 교체 (N1)

| | 지금 | 바꿈 |
|---|---|---|
| 드라이버 | `com.mysql:mysql-connector-j` — **GPL-2.0** + FOSS Exception | `org.mariadb.jdbc:mariadb-java-client` — **LGPL-2.1-or-later** |
| URL | `jdbc:mysql://…` | `jdbc:mariadb://…` |
| 드라이버 클래스 | `com.mysql.cj.jdbc.Driver` | `org.mariadb.jdbc.Driver` |

- MariaDB Connector/J 는 **MariaDB 와 MySQL 둘 다** 붙는다.
  MySQL 8 의 기본 인증(`caching_sha2_password`)은 **2.5.0 부터 지원**한다(현재 3.5.x).
- URL 매개변수가 다르다: `useSSL=false` → `sslMode=disable`,
  `serverTimezone=` → 서버 시간대 설정, `allowPublicKeyRetrieval` 불필요.
  `rewriteBatchedStatements=true` 는 그대로 있다(배치 저장에 필요).
- Flyway 는 `flyway-mysql` 모듈이 MariaDB 도 덮는다. Hibernate 방언은 자동 판별되며,
  어긋나면 명시한다.
- **서버도 MariaDB 로 바꾸는 것을 함께 검토한다.** 이미 `check-mariadb.sh` 가
  MariaDB 10.11 로 전체 시험을 돌리고 있다 — 바꾸면 **시험하는 것과 운영하는 것이
  같아진다.** MySQL 8 을 그대로 둬도 위 드라이버로 동작한다.
  (DB 서버는 별개 프로그램이라 라이선스가 우리 코드에 옮지 않는다. 드라이버만이 문제다.)

  붙고 다른 자산엔 안 붙어 있으면 **묶음이 갈려 "2대" 가 "1대" 가 된다.**

**어휘 — 앞서 "전부 고쳤다" 고 보고했으나 남아 있던 것** (§4.1)

뜻이므로 `VocabularyTest` 로 못 박았다 — 화면에 나가는 글자만 보고, 무엇을 왜
바꿨는지 적은 주석은 건드리지 않는다.

`승인한 사람` 은 N5 로 미루지 않고 여기서 없앴다. 되살려 놓은 것이 나이므로

`approved_by` 다** — N5 의 V11 에서 이 표를 다시 만들 때 함께 바꾼다.

- **`감추기` 체크박스 없음** — 상태가 정한다 (§4.5). 거르개는 `검토 끝난 것도 보기` 하나

  한 칸에 두면 누가 말한 것인지 구분되지 않는다 (CLAUDE.md 11)

**띄워 보고 찾은 것** (시험 227개가 전부 통과한 채로 있던 것):

적어 둔 검토 결과가 **취약점 목록에 안 붙었다.** 키를 `finding.cve`(grype 의 주
식별자)로 잡았는데, grype 이 GHSA 를 주 식별자로 낸 건은 사람이 읽고 적는 것이
함께 온 CVE 번호다. 그래서 같은 건을 적어 놓고도 목록에는 "아직 안 적음" 으로
떴다. 화면에 찍는 번호로 키를 잡고, 옛 번호로 적힌 것(옮겨 온 행)도 찾도록
두 번호를 모두 본다.

그 시험을 처음엔 `html.contains("해당 없음")` 으로 썼다가 **고치기 전 코드에서도
통과했다** — 같은 화면에 있는 대화상자에 다섯 상태가 전부 들어 있어서 언제나
걸렸다. 행이 그린 것만 보도록 고쳤다.

**어휘 — §4.1 과 §4.3 이 `근거` 를 두 가지에 쓰고 있었다**

자유 입력 칸(`사유`→`근거`)과 `해당 없음` 일 때 고르는 표준값. §4.0 규칙 2 와
충돌한다. **고르는 것을 `근거`, 적는 것을 `설명`** 으로 갈랐다.

### N5b — `/actions` 두 탭 ✅
- 새 `ActionController`(`/actions`) — `조치` 와 `검토 결과` 두 탭.

  **목록만 보고 무엇을 조치할지 고를 수는 없다**
- 자산 상세의 `조치·검토` 탭에 **검토 결과를 넣었다.** 탭 이름은 그런데 조치만
  있었고, 검토 결과는 대응 화면에서만 볼 수 있어 "이 서버 것만" 을 물을 자리가
  없었다 (§1 지적 7)

**어휘 — 없는 승인이 하나 더 있었다.** `RemediationStatus.ACCEPTED` 의 화면
이름이 `예외 승인` 이었다. 아무나 눌러 닫을 수 있는 상태에 '승인' 을 붙이면
통제가 있는 것처럼 보이는데 실제로는 없다. `하지 않고 닫음` 으로 고쳤다.

> **남은 겹침 — 결정이 필요하다.** "안 고치기로 했다" 는 판단은 이제 검토
> 결과의 대응(`조치 안 함`)이 담는다. 조치 상태의 `ACCEPTED` 는 *그 판단이
> 아니라 조치 하나가 닫힌 상태*인데, 둘이 가까워서 어느 쪽을 봐야 할지
> 헷갈릴 수 있다. 없애고 검토 결과로 모으려면 값이 DB 에 글자로 들어 있어
> 마이그레이션이 필요하다 — 화면을 합치는 단계에서 함께 하지 않았다.

### N6 — 계정 ⚠ V12 ✅
- `AccountService.update(username, displayName, role, enabled, newPasswordOrNull, actor)`
  — `changeRole` 과 `setEnabled` 를 여기로 합쳤다. 권한을 바꾸는 길이 둘이면
  한쪽에만 '마지막 관리자' 보호가 걸린 채로 남는 날이 온다
- 새 `MeController`(`/me`), `me.html` 카드 둘. `/me` 임시 다리 제거
- `settings.html` 계정 `[수정]` 팝업. **권한 드롭다운 즉시 저장 제거** —
  실수로 스친 것과 정말 바꾼 것을 가르지 못했고 되돌릴 자리도 없었다
- `AuditEvent.USER_UPDATED`
- 비밀번호 칸은 **비우면 안 건드린다.** 정해 주면 본인이 받아서 곧바로 다시
  바꾸게 한다(`mustChange`) — 관리자가 아는 비밀번호를 그대로 쓰게 두지 않는다

**`users.last_login_at` 이 한 번도 채워지지 않았다** (N1 에서 발견). 열은 V1
부터 있었고 화면 둘이 그 값을 읽고 있었는데 `setLastLoginAt` 을 부르는 곳이
코드 어디에도 없었다.

> **그런데 로그인할 때 채우기만 하면 반대로 뒤집힌다.** 비밀번호 변경 화면은
> `lastLoginAt == null` 로 "최초 로그인" 과 "관리자가 초기화함" 을 갈랐는데,
> 그 화면은 로그인 **다음 요청**에서 뜬다 — 이미 이번 로그인 시각이 박혀 있어
> 이번에는 전부 '임시 비밀번호' 가 된다. 순서로는 풀리지 않는다.

**V12 — 사실 두 개를 두 칸에 나눠 적는다.**

```
last_login_at      이번에 들어온 시각     → 설정의 '마지막 로그인'
previous_login_at  그 전에 들어온 시각    → NULL 이면 이번이 처음
```

날짜 하나로 눈치껏 가르려 하면(만든 시각과 비교한다든지) 언젠가 틀리고
틀린 줄도 모른다. 이미 쓰던 설치는 **감사 로그의 로그인 성공 기록으로
채운다** — 지어내는 것이 아니라 우리가 이미 가지고 있는 값이다.

#### ② 삭제를 시험으로 지킬 수 없었다

`AssetService.delete` 를 도는 시험이 **하나도 없었다.** 화면에 삭제 단추가
있고 지우는 것이 몇 건인지까지 세어 보여 주는데도.

원인은 **엔티티 쪽 `@OnDelete` 가 빠진 것**이었다. Flyway 의 FK 에는
`ON DELETE CASCADE` 가 있는데 하이버네이트가 만드는 H2 스키마에는 없으니,
그 삭제를 도는 시험을 쓰면 **H2 에서만** 참조 제약 위반이 났다. N9 에서
`component` 를 고칠 때 이미 만난 것과 같은 것이고, 나머지 다섯에 남아 있었다.

| 고친 자리 | 마이그레이션 |
|---|---|
| `Finding.scan` · `Remediation.asset` · `RemediationEvent.remediation` · `FindingAnalysis.asset` · `FindingAnalysisEvent.analysis` | 전부 이미 CASCADE — 엔티티 표시만 없었다 |

> **처음에 "운영에서 삭제가 실패한다" 고 적었는데 틀렸다.** `ON DELETE CASCADE`
> 가 SQL 의 **다음 줄**에 있어 한 줄만 보는 `grep` 이 놓쳤다. 파일을 열어
> 읽고, 검토 결과가 있는 자산을 실제로 지워 확인했다 — 운영은 정상이다.

새 시험 둘과 가늠막이 하나.

- `AssetDeleteTest` — 검사·탐지·조치·검토 결과가 **함께** 사라지는가
- `CascadeParityTest` — 마이그레이션의 `CASCADE` 와 엔티티의 `@OnDelete` 가
  일치하는가. **양방향으로 본다**: 엔티티에만 있으면 시험이 운영보다 관대해져
  "시험은 지워지는데 운영에서 FK 위반" 이 된다
- 지운 기록에 **검토 결과 건수**가 남는가 — 확인 상자는 세어 보여 주는데
  감사 로그와 완료 안내에는 빠져 있었다. 파괴적 작업의 기록이 실제보다 적게
  남으면 점검에서 답이 어긋난다

> `CascadeParityTest` 도 **처음 짠 것은 표시를 떼고도 통과했다.** 열 이름만으로
> 묶어서 `component` 의 `scan_id`(CASCADE)가 `findings` 의 빈 자리를 덮었다.
> (표, 열) 쌍으로 고치고 양방향으로 확인했다 — 규칙 8.

#### ③ 실패한 검사의 패키지가 화면에 남았다

담기는 쓰는 대로 커밋되고 `makeCurrent` 는 다 담은 뒤에 부른다. 그래서 중간에
터지면 **새 검사 것과 이전 검사 것이 한 자산에 함께 남고**, 패키지 화면이 한
패키지를 두 버전으로 보여 준다 — 그것이 "두 대에 다르게 깔렸다" 와 구분되지
않는다. N11 에서 79행을 손으로 지운 것이 이 자리다.

`runAsync` 의 실패 처리에 `inventory.discard` 가 없었다. 더했고,
`ComponentInventoryTest#failedScanLeavesNoInventory` 가 지킨다.

> 그 시험도 처음엔 상태만 보고 기다렸다. `markFailed` 가 먼저, `discard` 가
> 나중에 불리므로 **discard 전에 깨어났다** — 전체 시험에서만 어긋났다.
> 재야 하는 것은 상태가 아니라 남은 행이었다.

#### ④ `ScanService.run` 의 `@Transactional` 은 죽은 표시였다 — 지웠다

`runAsync` 가 같은 빈의 `run` 을 부르므로 프록시를 지나지 않아 애초에 효력이
없었다. **살려도 안 된다** — 대부분이 grype 이 도는 시간이고, 그 내내
트랜잭션을 붙잡으면 진행 표시가 끝나는 순간 한꺼번에 뜬다.

그 표시를 믿고 짠 자리가 있었다. `reapStale` 의 주석이
*"`run` 이 한 트랜잭션이라 프로세스가 죽으면 대개 함께 되돌려진다"* 고 적고
있었는데, 되돌려지는 일은 처음부터 없었다. 주석과 판단 근거를 실제와 맞췄다.

| 재검토일 | 없음 | **반드시 받는다** |
| 결재 문서 번호 | 없음 | 적는 칸이 있다 |

근거도 재검토일도 없이 아무나 눌러 닫을 수 있는 상태는 통제가 있는 것처럼
보이는 만큼 없느니만 못하다(§4.6). 앞서 이 상태의 화면 이름이 `예외 승인`
이어서 이름을 고쳤는데, 이번에는 **상태 자체**를 없앤다.

이미 닫아 둔 행은 **대기로 되돌리고 그 사실을 메모와 이력에 남긴다.** `완료`
로 바꾸면 하지 않은 일을 했다고 적는 셈이고, 조용히 지우면 누가 언제 닫았는지
사라진다. 사람이 적어 둔 메모는 **덮지 않고 이어 붙인다.**

`check-migrations.sh` 가 데이터가 있는 DB 에 ACCEPTED 2행(메모 있는 것·없는 것)
과 완료 1행을 넣고 다섯 가지를 확인한다 — 남은 ACCEPTED 0 · 되돌린 2행 · 메모
보존 · 이력 2줄(`from ACCEPTED → to OPEN`) · 완료는 그대로.

화면에서 그 선택지를 찾는 사람에게 어디로 가라고 각주로 말한다
(`action-detail.html`).

```

DB_PORT=13306 ./scripts/check-mariadb.sh      274개 통과 (MariaDB + Flyway)
DB_PORT=13306 ./scripts/check-migrations.sh   통과 (V14 포함, 데이터 있는 DB)

```

#### 안 한 것

- **`CVE-2025-41249` · `CVE-2025-41242`** — 6.1.x 에 수정 버전이 없다.

#### 서비스로 올리기 — 없던 것

띄우는 길이 `run-server.ps1` **하나뿐이었다.** 앞단에서 돌므로 창을 닫거나 PC
가 재부팅되면 내려간다. 팀이 함께 쓰는 도구가 그러면 **언제부터 안 됐는지
아무도 모른다.** `docs/` 와 `scripts/` 를 훑어 "서비스로 · 작업 스케줄러 ·
자동 시작 · 재부팅" 을 찾아봤고, 나온 것은 MariaDB 자동 시작 한 줄뿐이었다.

`scripts/install-service.ps1` 을 더했다. **작업 스케줄러**를 쓴다 — 윈도우에
들어 있는 것이라 폐쇄망에 반입할 것이 없다(NSSM 같은 것을 쓰지 않는 이유).

```
트리거   시스템 시작 1분 뒤 (DB 가 먼저 올라와야 한다)
계정     SYSTEM — 로그온하지 않아도 돈다
실패 시  1분 뒤 다시 시작, 세 번까지
기록     logs\service.log (10MB 를 넘으면 .1 로 밀어 둔다)
```

짜면서 걸린 자리들 — 전부 **조용히 실패하는** 쪽이라 적어 둔다.

| 자리 | 그냥 두면 | 어떻게 |
|---|---|---|
| 창이 없다 | 콘솔에 찍히던 것이 **전부 사라진다** — 최초 관리자 비밀번호도, 기동 실패 이유도 | `java`(`javaw` 아님) + 한 줄씩 `logs\service.log` 로. 창을 아끼려다 실패 이유를 잃는다 |
| 포트 기본값 | 서비스는 `env.ps1` 만 읽으므로 `SBOMSIGHT_PORT` 가 없으면 `application.yml` 의 **8443** 으로 떨어진다 — 설치 문서가 안내한 `https://localhost` 가 안 열린다 | 만들어 두는 launcher 가 `run-server.ps1` 과 같은 443 기본값을 준다 |
| 끝 코드 | `powershell.exe -File` 은 스크립트가 `exit` 하지 않으면 **0 으로 끝난다.** 자바가 DB 접속 실패로 죽어도 작업 스케줄러는 성공으로 보고, 걸어 둔 '실패 시 다시 시작' 이 한 번도 동작하지 않는다 | launcher 끝에 `exit $LASTEXITCODE` |

| SYSTEM 의 사용자 폴더 | grype 취약점 DB 는 사용자 캐시에 있다. **로그인 계정으로 받아 둔 DB 를 SYSTEM 이 못 본다** | `GRYPE_DB_CACHE_DIR` 을 두 쪽이 같은 자리를 보게 못 박으라고 세 문서에 적었다 |
| 판올림 | 도는 동안 jar 가 잠겨 `mvnw clean package` 가 **그 파일을 못 지우고 실패한다** | `-Stop` / `-Start` 를 같은 스크립트에 두고, 판올림 절차의 첫 줄로 박았다 |

### N14 — 화면의 바탕을 Tabler 로 바꾼다 ✅

**"새로고침하면 크기가 들쭉날쭉하고 단추 크기가 제각각이다. 차라리 외부의 잘
만들어진 것을 그대로 쓰면 안 되나" 는 말에서 시작했다.** 먼저 재 보니 두
가지가 섞여 있었다.

#### ① 흔들림은 CSS 가 아니라 응답 머리였다

스프링 시큐리티가 모든 응답에 붙이는 `no-store` 가 정적 파일에까지 붙어서,
**새로고침마다 글꼴 28개를 처음부터 다시 받고 있었다.** 한국어 글꼴은 293개
파일로 쪼개져 있어 도착 순서가 매번 다르고, 도착 전에는 대체 글꼴로 그려졌다가
도착하면 다시 그려진다 — 글자 폭이 달라지면 표의 칸과 단추가 함께 달라진다.

서버가 받은 요청을 세어 확인했다: `no-store` 는 `[1, 1, 1]`, 고친 뒤는
`[1, 0, 0]`. **프레임워크를 바꿔도 이것은 그대로였을 것이다.**

#### ② 그러고도 남는 불일치는 잰 값으로 있었다

| | 재기 전 | 지금 |
|---|---|---|
| 단추 모양 | **4가지** (20개는 클래스가 아예 없었다) | **2가지** (보통 40px · 작은 28px) |
| 입력칸 높이 | **39 · 40 · 41** | **2가지** (보통 40px · 작은 32px) |
| 표 칸 여백 | 5가지 | 2가지 (첫 칸만 다르다 — 카드 여백) |
| 제목 | 7가지 | 4가지 (화면 · 팝업 · 카드 · 문서) |

`scripts/check-uniform.py` 가 이 숫자를 센다. 눈으로 다투지 않으려고 만들었다.

#### 무엇을 가져왔나

**Tabler 1.5.1 (MIT) 의 CSS 한 장.** `dist/libs/` 는 통째로 뺐다 — 그 안의
ApexCharts 는 5판부터 MIT 가 아니고(재배포는 별도 OEM 라이선스) 우리는 차트를
쓰지 않는다. **JS 도 안 가져왔다** — 메뉴는 `<details>`, 팝업은 `<dialog>` 라
브라우저가 연다. 폐쇄망이므로 CDN 이 아니라 파일을 저장소에 담는다(694KB,
응답 압축을 켜서 90KB 안팎으로 나간다).

우리 `app.css` 는 919줄에서 **Tabler 가 모르는 것만** 남겼다 — 심각도 팔레트와
그 표시, 구역 색 띠, 검사 진행 눈금, 좁은 화면에서 첫 칸을 붙여 두는 표,
인쇄용 보고서.

#### 고치면서 걸린 것

- **`.alert` 는 이제 Tabler 의 알림 상자다.** 요약 줄의 링크에 그 이름을 쓰고
  있어서 "기한 지난 대응" 이 빨간 상자로 그려졌다 — `overdue` 로 바꿨다.
- **`.progress` 도 Tabler 것이다**(진행 막대). 검사 진행 칸은 `.progress-panel`.
- 시험 여섯 개가 옛 표식(`class="side"` · `zonegrid` · `btn small` ·
  `page-titlerow`)을 붙잡고 있어 함께 고쳤다. **뜻은 그대로 두고 표식만
  옮겼다** — 기둥이 있는가, 카드와 표가 갈리는가, 행 동작이 전부 단추인가.
- `FormLabelTest` 가 이름표 잃은 칸 여덟 개를 잡았다. `for`/`id` 로 묶었다.
- `check-contrast.py` 가 **멀쩡한 자리를 낮은 대비로 잡고 있었다** — 크로뮴이
  `light-dark()`·`color-mix()` 색을 `color(srgb …)` 로 돌려주는데 그 꼴을 못
  읽어 바탕을 흰색으로 보고 있었다. 읽게 고치고, 못 읽는 꼴은 세지 않고 따로
  적게 했다. 그러고 나서 잡힌 **경고 알림의 글자(2.0:1)는 진짜였다** — 진하게.

#### 확인

```
./mvnw -B test                     281개 통과
scripts/check-uniform.py           단추 2 · 입력칸 2 · 칸 2 · 제목 4
scripts/check-table-width.py 1280  넘치는 표 0
scripts/check-contrast.py          낮은 자리 0
scripts/check-links.py             빈 값 0
화면 26개 스크린샷                   전부 200 · 인쇄 화면까지 확인
```

#### 안 한 것

- **시안(`docs/preview.html`)은 그대로 두었다.** 이제 앱이 시안보다 앞선다 —
  나란히 놓고 보는 규칙(§7)은 이 판올림 뒤로는 시안을 다시 그리기 전까지
  뜻이 없다. 다시 그릴지는 정하지 않았다.
- 아이콘 세트는 가져오지 않았다. Tabler Icons 는 별도 패키지이고, 지금 화면에
  아이콘이 필요한 자리가 없다.

**기본은 펼친 상태로 두고, 접은 것은 이 브라우저의 이 세션에만 남긴다.**
주소에 넣지 않는 이유가 있다 — 그 링크가 결재 문서에 붙고, 받은 사람은 접힌
목록을 전체라고 읽는다. 구역 칩으로 걸러 놓았으면 접힌 것을 무시하고 펼친다
(걸러 놓고 빈 화면을 보는 일이 없어야 한다). 접어도 **구역 머리줄의 합계는
그대로 남는다** — 접은 것과 자산이 없는 것이 같아 보이면 안 된다.

#### 10번 — `몇 번째로` 는 쪽이 아니라 건의 번호다

화면이 `101–200번째` 라고 세고 있으므로 사람이 아는 값도 그 번호다. 서버가
쪽으로 환산해 되돌린다(`at` → `page`). `at` 은 주소에 남기지 않는다 —
남기면 거르개를 바꿀 때마다 따라다니며 엉뚱한 쪽으로 튄다.

#### 9번을 붙이면서 드러난 것 — `nullsLast()` 는 SQL 에 없었다

**오름차순을 열자 CVSS 가 없는 34건이 "가장 안 위험한 것" 자리에 줄줄이
섰다.** 띄워서 직접 보고 찾았다. 생성된 SQL 을 찍어 보니

```
order by f1_0.cvss_score, f1_0.package_name        ← nulls last 가 없다
```

`Sort.Order#nullsLast()` 는 Spring Data 의 정렬을 JPQL 에 붙이는 길에서
**그대로 사라진다.** 내림차순에서는 MySQL·H2 가 NULL 을 알아서 뒤로 보내
주므로 지금까지 맞아 보였을 뿐이다. 정렬 축 앞에 **"값이 없는가" 한 칸**을
직접 붙여 고쳤다(`VulnQuery.nullsLast`).

```
order by case when f1_0.cvss_score is null then 1 else 0 end, f1_0.cvss_score, …
```

지시만 보던 시험(`nullsLast()` 가 붙어 있는가)은 이것을 잡지 못했다.
**나온 목록을 보는 시험으로 바꿨다** — 두 축(CVSS·악용 확률) × 두 방향에서
값 없는 건이 맨 뒤인지 본다(`VulnScopeTest:290`).

심각도는 글자라 `ORDER BY CASE` 로만 낸다. 방향은 질의 안에서 뒤집고
(`:asc`), **심각도를 모르는 건은 방향과 무관하게 순위 9** 로 둔다.

#### 자산 1 — 왜 실제 악용을 맨 앞에 두는가

심각도는 grype 이 매긴 **등급**이고 실제 악용(KEV)은 지금 밖에서 쓰이고 있다는
**확인된 사실**이다. 심각 100건보다 실제 악용 1건이 급하다. 두 축이 다르므로
따로 센다 — 심각도가 `보통` 인데 실제로 악용되고 있는 건이 있다.

`kev` 는 **`= TRUE` 만 센다.** grype 이 값을 주지 않은 것은 "아니다" 가 아니라
"모른다" 이고, 그것을 악용 확인으로 세면 아무도 확인하지 않은 판정이 화면 맨
앞에 붉게 뜬다(`PageRenderTest:246` 가 막는다).

`심각`·`높음` 은 grype 이 준 단계 이름 그대로 둔다(§11). 등급을 `고위험` 처럼
다시 묶으면 그 묶음은 우리가 만든 판정이 된다.

#### 자산 2 — `보관` 이 무엇이 문제였나

이름이 목적을 말하지 않았다. 게다가 이 저장소에서 `보관` 은 **SBOM 원본을
gzip 으로 쥐고 있는 것**을 이미 가리키고 있었다 — 한 말이 두 가지를 가리키고
있었던 셈이다(§4.0.2).

하는 일은 **운영에서 내린 자산을 목록과 현황 숫자에서 빼는 것**이다. 주기적으로
SBOM 을 올리는 것으로 이 자리를 대신할 수 없다 — 폐기한 서버는 그냥 SBOM 이
안 올라오고, 그러면 마지막 검사가 영원히 "최신" 으로 남아 전사 심각 건수에
계속 더해지고 `30일 넘은 자산` 에도 계속 뜬다. 지우는 것과도 다르다: 지우면
검사 이력과 보고서 근거가 함께 사라진다.

**저장하는 열 이름(`archived_at`)과 감사 이벤트 이름(`ASSET_ARCHIVED`)은
그대로다.** 화면 말만 바꿨으므로 마이그레이션도, 이미 쌓인 기록의 뜻이 바뀌는
일도 없다.

#### 취약점 2 — `번째로` 를 걷어냈다

앞 회차에서 **건의 번호**로 이동하게 만들었는데(화면이 `101–200번째` 를 세고
있었으므로) 쓰는 사람이 기대한 것은 **페이지 번호**였다. 건수 줄의 `번째` 표시를
없애고, 칸은 페이지 번호를 받는다. 화면 말도 `쪽` → `페이지` 로 통일했다.

칸의 이름은 `page` 가 아니라 `jump` 다 — 주소의 `page` 는 0부터 세고(스프링의
셈) 사람이 읽는 페이지는 1부터다. 같은 이름으로 받으면 한 칸 어긋난 페이지로
간다. 서버가 환산해 `page` 로 되돌리고 `jump` 는 주소에 남기지 않는다.

### N18 — 패키지 화면의 체크박스 거르개 ✅

**"버전이 갈린 것만 · 취약점 있는 것만, 이거는 왜 안 고치는가."** 거르개 줄의
라벨은 맞췄는데 이 둘은 그대로 두었다.

#### 규칙 — 거르는 것은 고르개, 보기를 넓히는 것만 체크박스

| 무엇 | 모양 | 어디 |
|---|---|---|
| **거른다** (값을 골라 목록을 좁힘) | **고르개** | 구역 · 유형 · 취약점 · 버전 갈림 · 심각도 · 실제 악용 · 수정 버전 |
| **보기를 넓힌다** (숨긴 것을 함께 봄) | 체크박스 | 운영 종료 자산 포함 · 검토 끝난 것 포함 |

패키지 화면의 두 체크박스가 하는 일은 취약점 화면의 `심각도 전체`·`수정 버전
전체` 와 같은 **거르기**인데 모양만 달랐다. 한 줄 안에서 고르개는 값을 고르고
체크박스는 켜고 끈다 — 조작이 두 가지로 섞여 있었다. 고르개로 맞췄다.

```
전  구역[전체] 유형[전체] [패키지 이름] ☐취약점 있는 것만 ☐버전이 갈린 것만 [찾기]
후  구역[전체] [패키지 이름] [유형 전체] [취약점 전체] [버전 전체] [찾기]
```

값이 없을 때 **`전체` 를 그 칸의 이름과 함께** 적는다(`취약점 전체`) — 닫힌
고르개만 보고도 무엇을 거르는 칸인지 읽혀야 한다. `갈림` 한 마디로 줄이지
않는다: 무엇이 갈렸는지 알 수 없다. 검색칸을 앞으로 옮긴 것도 취약점 화면과
같은 차례로 두기 위해서다(`구역 → 검색 → 값 거르개 → 찾기`).

대응 화면의 `검토 끝난 것도 보기` 는 **보기를 넓히는 것**이라 체크박스로
두되, 맨 글자를 `form-check-label` 로 감싸고 이름을 `검토 끝난 것 포함` 으로
맞췄다(자산 목록의 `운영 종료 자산 포함` 과 같은 꼴).

#### 고치다 시험에 걸린 것

거르개를 고르개로 바꾸면서 `boolean` → `Boolean` 으로 받게 했는데(빈 값
`전체` 가 오므로 원시형이면 400 이 된다), **자바 매개변수 이름을 바꾸는 바람에
주소의 이름까지 함께 바뀌었다** — `?mixed=true` 가 아무 데도 안 붙어 거르개가
조용히 꺼졌다. `@RequestParam(name = "mixed")` 로 못 박았다. 화면만 봤으면
"눌러도 안 걸리네" 로 끝났을 자리다(`ComponentInventoryTest` 가 잡았다).

#### 확인

```
./mvnw -B test                             288개 통과 (H2)
DB_PORT=13306 scripts/check-mariadb.sh     288개 통과 (MariaDB 10.11 + Flyway)
scripts/check-rows.py                      0 · check-uniform 2/2/2/4
check-table-width 1280 → 0 · check-contrast 0 · check-links 빈 값 0
```

`FormLabelTest` 에 **체크박스 글자가 `form-check-label` 로 감싸였는가**를 더
했다 — 맨 글자로 두면 Tabler 가 이름표로 보지 않는다. 감싸기 전 코드에서
실패를 확인했다(`actions.html:49`).

띄워서 직접: 패키지 화면에서 `취약점 있는 것만` → 주소에 남고 고른 값이
유지되는 것, `버전 갈린 것만` → 7개 중 4개로 줄고 부제도 `7개 중 4개` 로
바뀌는 것, 유형까지 겹쳐 1개, CSV 주소가 같은 거르개를 들고 가는 것.

### N19 — `버전이 갈린 것만` 이 무엇을 거르는지 말하지 않았다 ✅

**"왜 버전이 갈린 거냐고, 그게 뭘 말하는지 직관적이지 않아서 뭐 하는 단추인지
모르겠다."** 앞 회차에서 이 거르개의 **모양**(체크박스 → 고르개)만 고치고
**이름**은 그대로 두었다. 이름이 문제였다.

#### 무엇을 거르는 것인가

`mixed` 는 <b>걸린 것이 있는 버전과 없는 버전이 한 패키지에 함께 깔려 있는
경우</b>다. 뜻은 하나다 — **일부 자산은 올렸고 일부는 안 올렸다.**

```
curl   ○ 8.6.0  3대     ▮ 8.4.0  2대     ← 3대는 올렸고 2대가 남았다
```

`버전 갈림` 은 그 사실도 그 뜻도 말하지 않는다. "무엇이 갈렸나 · 왜 갈렸나"
를 다시 물어야 하는 이름이었다.

| 자리 | 전 | 후 |
|---|---|---|
| 거르개 (고른 값 없음) | `버전 전체` | **`업그레이드 상태 전체`** |
| 거르개 (고른 값) | `버전 갈린 것만` | **`일부 자산만 업그레이드`** |
| 행 딱지 | `버전 갈림` | **`일부만 업그레이드`** |

둘 다 `title` 에 근거를 붙였다 — *걸린 것이 있는 버전과 없는 버전이 함께
깔려 있음 · 안 올린 자산이 남았다는 뜻*. 화면에 문장을 늘어놓지 않으면서
"왜" 를 남기는 자리다.

**주소의 이름(`?mixed=true`)은 그대로 둔다.** 적어 둔 주소와 즐겨찾기가
죽지 않게 — 화면 말만 바꾼다.

#### 확인

```
./mvnw -B test                             288개 통과 (H2)
DB_PORT=13306 scripts/check-mariadb.sh     288개 통과 (MariaDB 10.11 + Flyway)
scripts/check-rows.py 0 · check-uniform 2/2/2/4 · check-contrast 0
```

띄워서 직접: 닫힌 고르개가 `일부 자산만 업그레이드` 로 읽히는 것 · 7개 중
4개로 줄고 그 넷의 버전 조각이 전부 `○ 새 버전 3대 / ▮ 옛 버전 2대` 인 것 ·
딱지와 고르개의 `title`.

### N21 — 패키지별 묶기가 거르개를 버리고 있었다 ✅

취약점 화면의 `패키지별` 묶기만 **검색어 · 심각도 · 수정 버전 · 실제 악용**
넷을 버리고 있었다. 화면에는 고른 값이 그대로 남아 있는데 **목록은 한 줄도
바뀌지 않았다.**

```java
case "cve"     -> findings.groupByCveIn(scope.scanIds(), term, sev, fixable, kev);
case "package" -> findings.groupByPackageIn(scope.scanIds());   // ← 넷을 버린다
```

**걸린 것처럼 보이는 거르개가 안 걸리는 것은 값이 틀린 것과 같다.** 쓰는
사람은 `심각` 만 고른 뒤 열다섯 줄을 보고 "심각이 열다섯 가지" 라고 읽는다.

| 자리 | 무엇 |
|---|---|
| `FindingRepository.java:454-461` | `groupByCveIn` 과 **같은 네 조건**을 같은 식으로. 넷 다 `null` 이면 안 거른다 |
| `FindingRepository.java:465-469` | `groupByPackageIn(scanIds, q, severity, fixable, kev)` |
| `VulnQuery.java:304-307` | 넷을 넘긴다 |
| `ZoneReportService.java:242-243` | `null, null, null, null` — **보고서는 거르지 않는다.** 기간 안의 것을 전부 센다 |

#### 확인

### N22 — 보고서의 장 번호가 건너뛰었다 ✅

4장(`수정 버전 없는 항목`)과 5장(`조치 진행 현황`)을 비면 **통째로 감추고**

결재로 올라가는 문서에서 번호가 비면 읽는 사람은 **빠진 장을 찾는다.**

#### 더 나쁜 것 — 세는 단위가 다른 것이 가려졌다
